1. Executive Summary

The macOS port of Mumble at Internal/app/Ports/macos/ is a structurally faithful mirror of the Windows canonical codebase at approximately 70% feature parity. The port includes a complete 4,115-line controller (mumble_mac.py), a Tk canvas-based island overlay, a full web UI via pywebview with Cocoa WKWebView, an Apple Silicon STT accelerator leveraging FluidAudio and Parakeet TDT on CoreML/ANE, and a comprehensive 5,571-line installation script. The core dictation pipeline — audio capture, transcription, AI dispatch, formatting, and paste — is functional and delivers the core Mumble experience to macOS users.

However, the audit reveals 53 distinct issues across 5 investigation areas, ranging from latent crash bugs to missing entire features. The most critical finding is that the Meeting module — a major advertised feature — exists as source files in the macOS port directory but is never imported or wired into the controller, rendering it completely inaccessible. Other critical issues include a latent AttributeError crash in Prompt Mode (a call site references a method that does not exist), a LaunchAgent label mismatch that can cause duplicate autostart instances, and the absence of the local LLM initialization path, which silently degrades offline smart-mode dictation quality.

The platform integration layer shows signs of careful attention to macOS conventions (LaunchAgent autostart, .command installer scripts, Apple Silicon acceleration) but remains incomplete in critical areas: no DMG packaging or code signing, an untested auto-update swap script, missing Gatekeeper quarantine handling in updates, and a stale Windows-only brand_exe.py shipped to macOS users. The codebase carries significant technical debt: approximately 2.5MB of shared module code is duplicated across three platform directories with no abstraction layer, 90+ silent exception handlers mask real errors, all 26 background threads are abandoned on shutdown with no graceful termination protocol, and the os._exit(0) call in _quit() is a documented band-aid for unmanaged thread lifecycle.

This report provides actionable guidance for every issue: each finding includes the exact file location, line numbers, code evidence, a clear explanation of why the problem matters, and a concrete suggested fix with an estimated implementation complexity (simple, moderate, complex, or architectural). The recommendations are prioritized from immediate crash fixes to long-term architectural refactoring, enabling the development team to address the most critical gaps first while planning for sustainability.

Meeting module exists in macOS port directory but is never imported or wired into the controller

The source files being present creates a false expectation that the feature works. This is the single largest feature gap between Windows and macOS.

Critical Bug — Latent Crash CTRL-014
_local_llm_generate IS defined (line 3095) but _init_local_llm() never called — local LLM path silently non-functional on macOS
Description

macOS _generate() at line 3176 calls self._local_llm_generate(raw, det_mode, context). The method IS defined at mumble_mac.py line 3095 and includes proper defensive checks (local_engine.local_llm_ready() guard, try/except). However, because _init_local_llm() is never called (see CTRL-003), the local LLM backend is never loaded and local_llm_ready() always returns False. When the cloud path fails or is unavailable — i.e., Pro Mode off, no API key set, or cloud call raises an exception — this call will raise AttributeError, crashing the offline dictation pipeline. All offline smart-mode dictations (Prompt, Email, Reply) will fail on macOS.

Why This Matters

Every dictation that reaches the local LLM fallback path will silently produce no output because local_engine.local_llm_ready() returns False. With Pro Mode off or no API key configured, ALL smart-mode dictations fail. The error is silently caught by the outer handler showing "Processing error" and the dictation is lost.

Critical Bug PI-001
LaunchAgent plist label mismatch between installer and autostart.py causes duplicate/phantom autostart instances
Description

The Install Mumble.command script creates a LaunchAgent plist at ~/Library/LaunchAgents/com.mumble.voice.plist with Label com.mumble.voice, while autostart.py manages a separate plist at ~/Library/LaunchAgents/com.mumble.app.plist with Label com.mumble.app. These are entirely different launchd jobs. Conversely, enabling autostart from the app creates a second LaunchAgent alongside the installer's one, potentially launching Mumble twice.

Why This Matters

Users who disable "start at login" from the app's settings will find Mumble still launching at login. Two concurrent Mumble instances could compete for audio devices, hotkeys, and the single-instance lock, causing erratic behavior or crashes.

# autostart.py defines:

# with Label: 'com.mumble.app'

Unify on a single label and plist file. Critical Resource Leak CQ-003
WebUI subprocess orphaned if controller crashes — no atexit/signal cleanup; webkit helpers survive indefinitely
Description

The web UI shell process (_webui_proc) is spawned via subprocess.Popen in _start_webui() and depends entirely on _quit() being called to terminate it. There is no atexit handler, no signal handler, and no __del__ method that would clean up the child process if the controller crashes, is killed externally, or exits via an unhandled exception. When orphaned, the pywebview host plus its WebKit helper processes continue running, holding the command port and consuming memory.

Why This Matters

On crash or force-quit, the web UI host becomes an orphaned process consuming system resources. The next Mumble launch will find the command port held by the zombie process, causing connection failures. This is the exact scenario _quit() was designed to prevent — but it only works when the method executes normally.

Location

Evidence

Register an atexit handler or SIGTERM signal handler that calls the webui cleanup logic (killpg + SIGTERM/SIGKILL fallback). This ensures orphaned webui processes are cleaned up regardless of how the controller exits.

High Missing Implementation CTRL-008 / PARITY-007

Description

Windows _quit() performs three safety operations: (1) saves partial dictation audio/text to history if recording was in progress, (2) unloads the local LLM backend and stops ModelProcessManager, (3) cancels in-flight HuggingFace model downloads preserving .part files. macOS _quit() performs NONE of these — only stops audio stream, unhooks keyboard, stops tray icon, kills webui process, destroys tk root, releases lock socket, and calls os._exit(0).

Silent data loss: quitting while recording loses all captured audio. Zombie LLM subprocesses waste resources. Interrupted model downloads must restart from scratch. This is a critical user-facing data loss scenario.

11. Performance Concerns

  • Canvas fallback renderer (OLUI-007): The Tk canvas fallback runs at 45ms (22fps) but the premium island_render pipeline is available. CPU time spent on Tk drawing could be redirected to rendering the premium output.
  • Dead import cost (OLUI-009): numpy and PIL are imported at startup (~50ms) for island_render but the output is never displayed due to glass pill being stubbed.
  • ANE resource leak (PI-007): MacOSTranscriber.unload() doesn't release GPU/ANE resources. On Apple Silicon, ANE memory is limited. Repeated model switches could exhaust it.
  • No Metal fallback (PI-011): Intel Macs and pre-macOS 13 users get CPU-only faster-whisper. mlx-whisper could provide 2-6x speedup on Metal.
  • Model default difference (PARITY-014): macOS defaults to base.en (142MB, lower accuracy) vs Windows small.en (466MB, higher accuracy). May be a deliberate memory tradeoff for Apple Silicon base models.

12. Code Quality Concerns

  • Thread lifecycle (CQ-001): 26 daemon threads, only 1 ever joined. os._exit(0) is the documented band-aid for unmanaged threads.
  • Silent exception swallowing (CQ-004): 90+ instances of except Exception: pass across critical paths. Makes debugging nearly impossible.
  • Code duplication (CQ-006): ~2.5MB of shared module code in 3 parallel directories. 70% estimated duplication.
  • No shared abstraction (CQ-008): Three controllers (~4000 lines each), three overlays (~1000-2600 lines). Any cross-cutting change touches 15+ files.
  • Subprocess orphan risk (CQ-003): WebUI host survives controller crash. No atexit or signal cleanup.
  • No signal handlers (CQ-010): SIGTERM/SIGINT cause unclean shutdown. Lock port stays bound after system restart.
  • Log file never closed (CQ-002): Crash logs may be lost. Relies on GC for cleanup.
  • TODO gap (CQ-005): Only 1 TODO marker across entire port. Known gaps untracked in source code.
  • Test coverage (CQ-007): Only 14 of 31 test files run automatically. 5 excluded due to API divergence.
  • Lock timeout silence (CQ-009): _tx_lock.acquire(timeout=N) returns empty string on failure — transcription silently lost.
  • Platform shadow duplication (PI-008): stdlib platform shadow workaround duplicated across two files.
  • Fragile pkill (PI-009): Installer uses pkill -f pattern matching — false positives and negatives on process termination.

13. UX/UI Inconsistencies

  • Dark title bar (OLUI-005): macOS app window has light title bar despite dark-themed content.
  • Fade-in animation (OLUI-006): Island snaps into view on macOS vs smooth fade-in on Windows.
  • Hotkey hint text (OLUI-010): Home tab says 'ctrl+windows' instead of 'ctrl+option+d'.
  • Hotkey documentation (PI-010): Installer says Ctrl+Option+M instead of actual default Ctrl+Option+D.
  • Click-through (OLUI-004): Behavior unverified — may not work on macOS.
  • Spaces awareness (OLUI-008): Island may appear on wrong desktop.
  • Accessibility indicator (OLUI-011): No visual warning when accessibility permissions are missing.
  • Companion bar styling (PARITY-015): macOS bar lacks the visual polish of Windows _WidgetBar.
