5Roadmap — Mumble V1 → Local AI Conversion

In plain terms

Mumble already has production local transcription and a guarded llama.cpp text-processing path, but it does not ship a text model. This roadmap promotes that foundation only after model licensing, download integrity, representative hardware measurements, cancellation, recovery, and cross-platform packaging are proved.

The product must always show which of its two stages—speech-to-text and text processing—is local or cloud-based. Local-only mode is an egress boundary, not a marketing label: it disables cloud transcription, cloud generation, and provider-key network checks.

Current boundary: Windows is canonical. Local Whisper transcription is production code. The llama.cpp/GGUF adapter, lazy construction, prompt contracts, deterministic fallback, and explicit settings are implemented and source-tested on Windows, macOS and Linux, but no model is selected, downloaded, verified, bundled, or performance-qualified. Mac and Linux hardware qualification remains pending.

Target architecture

ComponentContract
Transcription enginesOne job interface for bundled local Whisper and explicitly selected cloud STT; language/model capability, progress, cancellation and typed error events are reported without leaking provider details into the ordinary UI.
Text-processing enginesOne input/output contract for deterministic local formatting, llama.cpp/GGUF, Cerebras and OpenRouter. Modes supply versioned templates; validators reject empty, unrelated or contract-breaking output and fall back without losing the transcript.
Model managerOwns a signed catalogue, licence/notice metadata, resumable downloads, SHA-256 verification, available disk checks, versioned storage, activation, rollback and deletion. A user-selected file remains an advanced escape hatch.
Routing and privacyEach stage records its effective local/cloud route. Mixed mode is allowed only when clearly selected. Local-only is enforced at the egress call sites. Cloud keys move from masked local settings to OS credential storage with migration and deletion support.
Jobs and resourcesEvery transcription/download/generation job has an id, progress, cancellation token, timeout, terminal event and cleanup path. Only one local model owner controls context lifetime; crashes quarantine the model for that session and preserve the source transcript.
VerificationContract tests cover every engine; golden prompt cases cover names, numbers, URLs, corrections, multilingual text and instruction-injection attempts; hardware runs record latency, peak memory, cancellation and output quality.

8Architecture Review — Open-Source Findings (2026-06-28)

In plain terms

A comprehensive open-source architecture review was conducted on 2026-06-28. This section captures the key findings and decisions. The full detailed analysis lives in Other/research/architecture-review-2026-06-28.html. Items marked ✓ are confirmed decisions; items marked ⚡ need a spike before committing.

8.1 Windows Acceleration Beyond CUDA — Corrected Path

Finding: CTranslate2 only accelerates on NVIDIA CUDA GPUs. AMD, Intel, and integrated GPUs get zero GPU acceleration — affecting ~40% of Windows users.

Correction: DirectML exists, but the current sherpa-onnx Python/native recognizer does not expose a dml provider. Installing onnxruntime-directml does not change the separately bundled runtime used by sherpa-onnx. Mumble's old windows_dml.py is also unwired and its dependencies are not shipped; it is prototype code, not acceleration users receive.

Decision: benchmark first — Keep the now-optimised faster-whisper CPU/CUDA path in production. Evaluate Moonshine's queued Windows stream for English and whisper.cpp Vulkan for cross-vendor GPU use against the same Mumble corpus, installer and licence gates. No backend becomes automatic from an upstream speed claim alone.

8.2 macOS — FluidAudio + Parakeet TDT on Apple Neural Engine

Finding: FluidAudio (Apache 2.0, github.com/FluidInference/FluidAudio) runs Parakeet TDT on Apple's Neural Engine via CoreML. Benchmarks vs current faster-whisper:

Speed: 155–237× realtime vs 15–30× (5–10× faster)
Accuracy: 6.32% WER vs 7.44% (15% fewer errors)
RAM: ~66 MB vs ~500 MB – 1.5 GB (90–95% less)
Battery: Neural Engine ~2–3W vs GPU ~10–30W (no fans)
Hallucinations: Zero vs classic Whisper silence hallucinations
Trade-off: 25 European languages vs Whisper's 99 (keep Whisper as fallback for non-European languages)

Integration: Swift helper binary (FluidAudio is Swift) communicating via stdin/stdout JSON. ~200 lines Swift + ~100 lines Python glue.

Decision: ✓ adopt — P1 priority. Single highest-impact architectural change in this review.

8.3 Local LLM Post-Processing — Replacing the Cloud API

Goal: Replace Cerebras/OpenAI cloud post-processing with a fully local pipeline.

Finding: A multi-model pipeline beats a single general LLM for transcription post-processing. Each stage uses a purpose-built model:

Stage 1 — Punctuation: rpunct (BERT, ~80 MB, pip-installable). Restores . , ? ! and capitalisation. Near-perfect accuracy, runs in ~5ms. A dedicated BERT model is more accurate AND faster than an LLM for this specific task.
Stage 2 — Grammar: GRMR-2B-Instruct (2B params, ~1.5 GB GGUF). Purpose-built for grammar correction. Beats Llama-3.1-8B on this task despite being 4× smaller. Removes fillers, fixes grammar, cleans artefacts.
Stage 3 — Formatting: Qwen2.5-1.5B-Instruct (1.5B params, ~2 GB GGUF). Mode formatting — prompt structure, email skeleton, bullet lists, contextual replies. The existing LlamaCppBackend in local_engine.py is fully coded and just needs a GGUF model file.
Stage 4 — Surface: Existing formatting.py — spacing, glued punctuation, contraction fix. Already implemented and tested.

Cloud replacement viability: This pipeline handles ~90% of usage at near-cloud quality. Heavy presets (multi-document, contextual replies with long history) still benefit from cloud — the existing UPGRADE_NOTICE degradation handles this gracefully.

Decision: ✓ adopt — P0: Wire Qwen2.5-1.5B via existing LlamaCppBackend (1–2 days, code is already written). P4: Add rpunct pre-pass (1 day). P5: Evaluate GRMR-2B (spike).

8.4 New STT Contender — Cohere Transcribe (March 2026)

Finding: Cohere released a 2B-param STT model (Apache 2.0) achieving 5.42% WER — beating Whisper (7.44%) and Parakeet (6.32%). Supports 14 languages including English + Asian/Middle Eastern languages Parakeet misses (Japanese, Korean, Chinese, Arabic, Hindi).

Caveat: Very new (3 months). No CTranslate2 or ONNX port yet. Inference requires PyTorch — heavier than CTranslate2. Ecosystem immature.

Decision: monitor — Watch for a CTranslate2/ONNX port. Could become the single best model for all platforms.

8.5 Audio Pre-Processing — DeepFilterNet3

Finding: deepfilternet (pip install) provides real-time AI noise suppression that outperforms RNNoise. Cleans keyboard clicks, fan hum, cafe chatter before STT.

Decision: ⚡ spike — Evaluate whether accuracy gain in noisy environments justifies ~5ms latency cost.

8.6 Linux — PipeWire, Wayland, ARM

PipeWire: Already supported via PortAudio. No changes needed.
Wayland: Linux has an evdev input path for global hotkeys (the user must have readable /dev/input/event* devices, normally via the input group) and ydotool/wl-clipboard output fallbacks. Real compositor behaviour remains a hardware gate.
ARM: whisper.cpp provides ARM Neon optimised inference. Add as Linux fallback.

8.7 What We Are KEEPING (Near-Optimal)

• Audio Capture: sounddevice/PortAudio — industry standard, no worthwhile alternative.
• VAD: Silero VAD — best open-source VAD, already integrated.
• Streaming: The corrected four-second worker has exact sample seams, same-session in-flight harvesting and stale-worker guards. It is the production bridge, not the final word: a genuine streaming engine still needs corpus and packaging evidence.
• Cloud Post-Processing: ai/ package with multi-provider — sound architecture, cloud is a commodity.
• Overlay/Island: Custom Pillow + Win32 — unique to Mumble, no equivalent exists.
• Update System: Manifest + zip + atomic swap — correct for a Python app.
• Data Layer: Settings, history, clipboard, stats, cloud sync — all well-scoped.
