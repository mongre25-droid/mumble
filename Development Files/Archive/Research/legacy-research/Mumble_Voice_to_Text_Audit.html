01 · Executive verdict

The previous audit stopped where the real work should have begun.

Mumble is already more feature-rich than most small dictation repositories, but its breadth is ahead of its boundaries. The highest-return improvements are not another settings page or a wholesale model swap. They are enforceable egress policy, a bounded capture session, confirmed/volatile streaming text, ownership-aware native insertion, a shared core with narrow platform adapters, and honest meeting capture/timestamps.
P0

Privacy routing

Local-only is computed but not enforced at both Cloud STT and cloud post-processing boundaries.

P0

Licence gate

The shipping manifest includes PyMuPDF and EbookLib under AGPL terms. EbookLib was incorrectly documented as BSD.

P1

Architecture

Large copied controllers and unwired platform backends make platform claims expensive and unreliable.

P1

Meetings

Current recording is microphone-only; timing and lightweight diarisation are heuristic rather than source-grounded.

P2

Streaming

Five-second periodic decoding is useful work reuse, not a stable partial-transcript architecture.

Strength

Product foundation

Local faster-whisper, Deck, Reader, Island, history, recovery, and paste retries create a strong base worth preserving.

04 · Privacy & egress proof

“Local-only” is currently a preference, not an enforced invariant.

Release blocker: mumble.py:_cloud_transcription_on checks the selected cloud mode/key rather than local_only_mode. Later, _process computes a route, but _generate does not use that decision to gate _cloud_generate. Audio and transcript therefore have separate bypass paths.

Retention compounds the routing risk: settings default to broad history/clipboard limits and provider keys are stored in JSON. Move credentials to DPAPI/Credential Manager, Keychain and Secret Service; make clipboard monitoring opt-in or short-retention; redact logs and expose deletion/rotation controls.

05 · Pinned source audits

Sixteen projects inspected at current commits.

FluidAudio Tier A Apache-2.0

Commit: d2937a8 (11 July 2026). A Swift SDK for Apple platforms—not a dictation application. It contains ASR families, streaming state, VAD, diarisation, model download/cache, punctuation commit logic, benchmarks and tests. Actor/queue ownership and explicit resource lifecycle are its strongest transferable lessons. Mumble would need a Swift helper/XPC or sidecar boundary; the current Python bridge sketch is not an upstream integration.

Package.swift · Architecture · ModelHub · Tests

FluidVoice by Altic Tier A GPL-3.0

Commit: 1f6ff00 (12 July 2026). A macOS dictation product with CoreAudio support code, ranked insertion strategies, focus-aware delivery, hotkey recovery, preview/final passes, per-app routing, history and optional analytics. Its package manifest pins a FluidAudio-related branch. Valuable concepts: dropped-packet accounting, low-latency preview followed by final retry, and clipboard ownership. Avoid its large service/settings surfaces, raw command execution patterns and privacy defaults. Clean-room reference unless Mumble deliberately accepts GPL compatibility obligations.

Manifest · Source · Tests

Handy Tier A MIT

Commit: ea10f74 (12 July 2026). Tauri/Rust desktop dictation with cached device configuration, explicit VAD modes, model management, accessibility permissions, packaged native transcription libraries and platform installers. The recorder/session design is the best direct reference for separating device acquisition, capture policy and transcription. Direct reuse is possible with retained MIT notice, but adaptation is safer than importing a large Tauri surface into Python.

Recorder · Dependencies · CI

OpenWhispr Tier A MIT

Commit: 5cac496 (10 July 2026). Electron application with local/cloud engines, native fast-paste helpers, multi-format clipboard snapshot/restore, macOS audio tap, Linux system-audio helper, meeting AEC, text monitoring, API-key UI and broad tests. Its platform helpers offer high-value behavioural and possible direct-reuse candidates, but each native helper and bundled dependency needs its own notice/security review. Mumble should borrow the full-format preservation and serialized delivery concepts.

Clipboard · Windows paste · macOS audio tap · Tests

OpenLess Tier A MIT

Commit: 414acf0 (12 July 2026). A broad Tauri/Rust voice-input project spanning desktop, Linux input methods and Android accessibility/IME work. Its insertion implementation records restore identity and verifies the current clipboard payload before restoration, directly addressing Mumble’s stale-restore race. It also demonstrates a capability-oriented route to Linux and Android rather than assuming simulated Ctrl+V is universal.

Insertion · Backend tests

RealtimeSTT Tier A MIT

Commit: a89fabb (12 June 2026). A library/server with multiple engines, audio workers, lifecycle separation and a dedicated real-time text stabilizer. It maintains stable, consensus and unstable text from timestamped observations. This is the strongest semantic reference for Mumble’s user-visible live transcript, though the surrounding dependency and server surface should not be imported wholesale.

Stabilizer · Core · Licence notes

sherpa-onnx Tier A Apache-2.0

Commit: 40b75e9 (10 July 2026). A mature cross-platform speech runtime with online/offline recognizers, endpoint rules, VAD, punctuation and bindings across desktop/mobile/web. Its C API provides the clean stream → accept waveform → decode → endpoint → reset contract Mumble’s backend abstraction lacks. Evaluate latency, accuracy, package size and model licences on each target before adoption.

C API · Examples · CI

WhisperX Tier A BSD-2-Clause

Commit: 8dcdec1 (26 June 2026). Batch transcription with VAD, forced alignment and optional pyannote diarisation. It is relevant to post-recording meetings, not short live dictation. Mumble should use its architecture as an opt-in enhancement pipeline and retain actual segment/word timing; model access and pyannote terms remain separate from WhisperX’s BSD licence.

Diarisation · Alignment · Manifest

VoiceInk Tier A GPL-3.0

Commit: cf0c366 (11 July 2026). Native macOS app with AUHAL/CoreAudio recording, preallocated buffers, device management, clipboard/cursor paste strategies, native Apple transcription, model services and Sparkle-style update metadata. Strong macOS lifecycle reference; GPL means clean-room behaviour unless Mumble changes its licensing/distribution approach.

CoreAudio recorder · Paste layer · Build

whisrs Tier A MIT

Commit: 7aec182 (29 June 2026). Linux-first Rust dictation with explicit ASR sidecars, silence gate, overlap deduplication, prompt echo handling, XKB typing and clipboard injection. Its small composable crates make useful direct or adapted candidates with MIT notices. The sidecar boundary is especially relevant if Mumble supports several native runtimes without loading all of them into the controller.

Local backend · Utility crates · Sidecars

Voxtype Tier A MIT

Commit: 31b7f38 (24 June 2026). Linux-focused Rust service with output drivers, modifier guards, session-aware clipboard handling, multiple ONNX/GPU packages, systemd integration and compositor-specific guidance. It is the strongest reality check against generic “Linux support”: X11, Wayland compositors, portal/input methods and packaging need explicit matrices.

Output abstraction · Packaging · Configuration

Buzz Tier A MIT

Commit: 191795b (2 July 2026). Mature Python desktop transcription application with model loading, file queues, recording transcription, database migrations, CUDA setup and installers. Its bounded/overlapped recording transcription and process separation are relevant; it is not a system-wide insertion product. Useful direct Python reference with MIT notice.

Recording transcriber · Model loader · Tests

WhisperLive Tier A MIT

Commit: d9459eb (6 July 2026). WebSocket service with faster-whisper, TensorRT and OpenVINO backends, bounded clients, metrics, translation and optional diarisation. It is a reference for an out-of-process transcription service and connection lifecycle, not for desktop capture or insertion.

Server · Backends · Tests

Meetily Tier A MIT

Commit: 0281737 (5 June 2026). Local meeting assistant with Rust/native helpers, Whisper/Parakeet paths, local summary workflows, database, update manifest and GPU build variants. It is the most relevant complete meeting-product comparison, but Mumble should verify capture source, diarisation and timing implementations individually rather than accepting “local” or speed claims from the README.

Architecture · Backend · GPU

TypeWhisper Windows Tier A GPL-3.0

Commit: 4200db2 (12 July 2026). Large .NET/WPF product with a typed core, plugins, staged native runtime installation, multiple local/cloud streaming providers, insertion services, privacy documentation and extensive tests. Its testable insertion interface and isolated optional pipeline failures are strong clean-room references. The plugin breadth also demonstrates why capability/egress declarations are necessary.

Source · Plugins · Tests

screenpipe Tier A Commercial/source-available

Commit: 6349ef5 (11 July 2026). Large always-on capture system with device watchers, audio reconciliation, persistence retries, analytics and broad platform code. Its operational recovery ideas are valuable for meetings, but the root licence is the Screenpipe Commercial License, not a standard open-source licence. Feature/clean-room reference only unless explicit terms permit the intended use.

07 · Feature and implementation gaps

What Mumble should learn—not merely copy.

Confirmed/volatile live text

Show committed words separately from changing hypotheses. RealtimeSTT and FluidAudio demonstrate explicit state; Mumble currently waits for final delivery.

Bounded capture with backpressure

Use timestamped rings, VAD/endpoint policy, dropped-frame metrics and device-loss recovery. Whole-session frame lists should not be the default.

Native text delivery

Preserve text, HTML, RTF, images/files where possible; mark clipboard ownership; restore only when unchanged; release stuck modifiers and retain target focus.

Real meeting sources

WASAPI loopback, ScreenCaptureKit/CoreAudio taps and PipeWire/Pulse adapters need independent capability matrices, permissions and tests.

Model lifecycle

Signed/hashed manifests, resumable downloads, corruption recovery, warm/cold state, resource ownership, explicit unload and per-device benchmarking.

Per-app policy

FluidVoice and mature dictation tools apply app-aware insertion and mode rules. Mumble can add this only after privacy and focus semantics are reliable.

Accessibility and input methods

Linux IBus/Fcitx and Android accessibility/IME work show that “paste everywhere” is a platform capability problem, not one keyboard simulation function.

Operational evidence

Expose real latency stages, dropped frames, model/device state and failures—never invented accuracy or fabricated word timing.

Do not import blindly

  • Huge plugin/provider catalogues before an egress capability model exists.
  • Raw shell-command execution from dictated text.
  • Always-on capture or analytics by default.
  • Repository star counts as quality evidence.
  • “GPU supported” claims without wired production callers and hardware tests.
  • Repeated full-buffer re-decodes disguised as true streaming.
  • Speaker labels inferred from pauses but presented as identity.
  • Native helpers without signing, sandbox and input validation review.

Immediate register correction: the live environment reports PyMuPDF==1.27.2.3 as AGPL-3.0 or commercial and EbookLib==0.20 as AGPL-3.0. The previous register called EbookLib BSD and understated the compatibility question. Both are now documented as release blockers.

09 · Decision-complete roadmap

Fix trust boundaries before adding engines.

Phase 0 — release gate

  1. Introduce one immutable EgressPolicy enforced by every audio, text, sync, diagnostic, update and plug-in transport. Replace boolean checks scattered through controllers.
  2. Add controller-level tests that stub all transports and prove strict local-only causes zero audio/transcript/model-discovery calls.
  3. Resolve PyMuPDF and EbookLib licensing; generate a clean-build SBOM and verbatim third-party notice bundle.
  4. Move provider secrets to OS vaults; migrate/delete plaintext values; make logs metadata-only and clipboard monitoring short-retention/opt-in.
  5. Authenticate the WebUI command socket using the existing session-token model.

Phase 1 — extract boundaries without a rewrite

  1. Extract CaptureSession → AudioRing/Resampler/VAD → TranscriptionBackend → TranscriptStabilizer → PostProcessingPipeline → TextDelivery behind the current UI.
  2. Keep faster-whisper as the first backend. Define capabilities for batch, online partials, timestamps, language, GPU and unload.
  3. Implement bounded timestamped audio storage, backpressure/drop metrics, endpointing and short/medium/long duration policies.
  4. Expose confirmed and volatile transcript events. Final insertion must reconcile against the committed sequence rather than concatenate arbitrary chunk strings.

Phase 2 — delivery and platforms

  1. Build native Windows/macOS/Linux TextDelivery adapters with ownership-aware restore, multi-format preservation where supported, modifier/focus tests and serialized operations.
  2. Move shared policy into one portable core. Platform controllers become narrow capture, hotkey, overlay, credential, insertion and update adapters.
  3. Evaluate FluidAudio via a real Swift helper on Apple platforms and sherpa-onnx/whisper.cpp/Parakeet behind benchmarks elsewhere. No UI claim before a production caller and hardware evidence exist.

Phase 3 — honest meetings and distribution

  1. Add system-audio capture per OS as separate projects. Persist source, channel, clock and real ASR timestamps; never infer word timing from character counts.
  2. Keep lightweight diarisation labelled heuristic. Offer alignment/diarisation only behind explicit model, consent, resource and licence gates.
  3. Produce clean allowlisted builds, dependency/model hashes, SBOM/notices, signed Windows artifacts, notarized macOS artifacts, provenance and three-platform CI.

Acceptance evidence

  • Strict local-only transport-call count is zero.
  • One-hour capture has bounded memory and no dropped audio under target load.
  • Device loss/sleep/resume tests recover deterministically.
  • Clipboard restore never overwrites a newer user clipboard.
  • Windows/macOS/Linux insertion matrices name tested apps and limitations.
  • Meeting exports use captured timestamps and source metadata.
  • Every packaged component appears in SBOM and notice bundle.
  • Installer/archive signatures and hashes verify on clean machines.
