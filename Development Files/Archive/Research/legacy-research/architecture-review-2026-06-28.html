In plain terms

This is a stock-take: for each part of Mumble (recognising speech, cleaning up the text, the window, updates, and so on) we asked "is there something open-source out there that would make this meaningfully better?" — and only flagged a swap when the answer was a clear yes, not a marginal one.

The short version: most of Mumble is already near-optimal and should be left alone. The real opportunities are (1) doing the "make it read well" clean-up on the user's own machine with a few small purpose-built models instead of the cloud, and (2) GPU speed-ups for the ~40% of Windows PCs that don't have an NVIDIA card.

2Local post-processing: multi-model pipeline replaces cloud API

In plain terms

One big general-purpose AI is not the best way to tidy up dictated text. Several tiny, single-job models — one just for punctuation, one just for grammar, one for shaping the result — each beat the big model at their own narrow task, while using a fraction of the memory. Stacked together on the user's own machine, they cover about 90% of everyday use at near-cloud quality.

Finding: A single general-purpose LLM is NOT the optimal approach for transcription post-processing. Purpose-built, lightweight models outperform general LLMs for narrow tasks at a fraction of the cost.

Cloud replacement viability: This multi-model pipeline handles ~90% of Mumble usage (text / prompt / email / list modes) at near-cloud quality. Heavy presets (multi-document reasoning, contextual replies) still benefit from cloud but degrade gracefully via UPGRADE_NOTICE.

Key insight: rpunct is a dedicated BERT model (pip install rpunct) that restores punctuation with near-perfect accuracy in ~5ms on CPU. It's both faster AND more accurate than asking an LLM to punctuate. GRMR-2B-Instruct is purpose-built for grammar correction and beats Llama-3.1-8B on this specific task despite being 4× smaller.

Existing code: local_engine.py already has LlamaCppBackend fully implemented — lazy loading, GBNF grammars, prompt caching. It just needs a GGUF model file to activate (currently defaults to NullBackend).

3Cohere Transcribe — new STT contender (March 2026)

Verdict: MONITOR  Could become the single best model for ALL platforms once the inference ecosystem matures (CTranslate2 / ONNX port). NOT recommended for production today.

  • Model: cohere-transcribe-03-2026, 2B params, Apache 2.0
  • WER: 5.42% (beats Whisper 7.44%, Parakeet 6.32%) — #1 on the Open ASR Leaderboard
  • Languages: 14 (English, French, Spanish, German, Italian, Portuguese, Dutch, Polish, Russian, Japanese, Korean, Chinese, Arabic, Hindi)
  • Speed: ~3× faster than Whisper
  • Caveat: Very new (3 months old). No CTranslate2 or ONNX port yet. Inference requires PyTorch (heavier). Ecosystem immature.

4GPU acceleration beyond CUDA — DirectML + ONNX Runtime

In plain terms

Today Mumble can only use a graphics card to go faster if it's an NVIDIA one. That leaves roughly 4 in 10 Windows users (AMD, Intel, laptop chips) stuck on the slower CPU path. Microsoft's DirectML runs on any modern graphics chip, so we can give those users a 2–5× speed-up with a single extra package.

The gap: CTranslate2 (under faster-whisper) only accelerates on NVIDIA CUDA. ~40% of Windows users (AMD Radeon, Intel Arc, integrated GPUs) get zero GPU acceleration.

The solution: Microsoft DirectML runs on ANY DirectX 12 GPU — NVIDIA, AMD, Intel, and NPUs on Copilot+ PCs. No vendor SDKs needed.

Implementation: sherpa-onnx (Apache 2.0, k2-fsa) packages SenseVoice, Paraformer, and Whisper models with DirectML, CUDA, and CoreML support. Single pip install sherpa-onnx.

Performance: 2–5× speedup on non-NVIDIA GPUs vs CPU-only. SenseVoice runs at 170× realtime on GPU.

5DeepFilterNet3 — audio pre-processing

Verdict: SPIKE  Evaluate whether the accuracy gain in noisy environments justifies the latency cost.

  • pip install deepfilternet
  • Real-time AI noise suppression outperforming RNNoise
  • Cleans keyboard clicks, fan hum, cafe chatter before STT
  • ONNX version (deepfilter-rt) runs ~5ms per 20ms audio frame

6RealtimeSTT — full-stack alternative?

Verdict: NOT RECOMMENDED as a replacement

RealtimeSTT (MIT, KoljaB) provides a complete audio-to-transcription pipeline: VAD, wake-word detection, streaming, and transcription using faster-whisper.

Mumble's custom streaming worker is already well-tuned. RealtimeSTT adds a dependency for marginal architectural gain. However, it's worth studying for ideas around wake-word activation.

7Linux Wayland hotkey blocking issue

Blocker for Linux Wayland — needs a spike

The keyboard library uses X11 APIs and will NOT work on Wayland. Alternatives:

  • pynput — partial Wayland support
  • libclicker (Codeberg) — full Wayland via uinput, requires root
  • Native helper binary — most reliable, platform-specific

10Final architecture

In plain terms

One shared Python core (UI, settings, history, clipboard, sync, post-processing, updates, overlay) sits on top of three platform back-ends. Each platform has a primary speech engine and a fallback: macOS leans on Apple's Neural Engine, Windows on NVIDIA or any-GPU DirectML, Linux on CUDA/CPU with a whisper.cpp fallback for ARM. The raw transcript then runs through the local clean-up stages, falling back to the cloud only for the heavy stuff.
