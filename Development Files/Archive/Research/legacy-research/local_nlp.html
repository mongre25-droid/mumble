Research

Local NLP Survey

◆Date: 2026-06-23
◆Target app: Mumble (Python desktop, faster-whisper STT, CPU-only)
◆Goal: Better offline post-processing, kept lightweight
◆Follow-on: LOCAL_POST_PROCESSING_ENGINE.html
In plain terms

When you dictate into Mumble, Whisper (the speech-to-text engine) turns your voice into text. But that raw text needs tidying: missing commas, the odd grammar slip, repeated words, and — most annoyingly — phantom phrases like “thanks for watching” that Whisper invents during silence. This report surveys the tools and tricks that can clean all that up on your own computer, with no internet and no big downloads.

The headline finding: the cheapest fixes are also the most valuable. A small list of known junk phrases plus a few grammar rules removes Whisper’s most embarrassing mistakes for free. Heavier machine-learning models are nice-to-have extras for people who opt in, not the foundation.

This is the companion survey to the Local Post-Processing Engine. The architecture this research feeds is specced in LOCAL_POST_PROCESSING_ENGINE.html (hybrid local/cloud router, local Foreign-Mode engine, GGUF/GBNF local smart-mode lanes) — partly shipped.

0Current state of Mumble’s post-processing

In plain terms

Mumble already does some cleanup with plain rules (no AI). It strips “um” and “uh”, fixes capital letters, adds a final full stop, corrects misheard vocabulary, and flags shaky words for the cloud AI to double-check. What it can’t do offline yet: smart punctuation, grammar fixes, and guarding against Whisper’s invented phrases. That’s the gap this report tackles.

Derived from mumble/formatting.py (the offline, rule-based engine):

  • Filler removal: regex _FILLER_RE strips um/uh/er/ah/hm/mm/mhm/you know (already implemented).
  • Capitalisation: _capitalize() handles sentence-start capitalisation, preserves intercaps (iPhone, macOS), handles the pronoun “I”, guards against breaking decimals/abbreviations.
  • Punctuation: _ensure_terminal() adds a trailing period; spacing fixups for glued punctuation. There is no comma/question-mark insertion beyond what Whisper emits.
  • Vocabulary correction: phonetic-key + Levenshtein matching (apply_vocabulary_terms), high-confidence auto-fix, medium-confidence slash annotation for AI review.
  • Confidence handling: annotate_uncertain() marks low-probability words with heard//alt slash alternatives for the cloud AI to resolve.
  • AI cleanup: Cerebras/OpenAI (Pro Mode) does grammar/punctuation/style. The offline path has none.
Gaps this report addresses: ML-based punctuation restoration, grammar correction, confidence recovery, hallucination/de-looping guards, and better text normalisation — all CPU-friendly and < 500 MB.

1Lightweight punctuation restoration

In plain terms

Whisper already adds some commas and full stops, but it gets sloppy on short or noisy clips. A dedicated “punctuation restorer” reads a sentence and puts the marks back in the right places. The options below range from a 1.3 GB multilingual model down to a few free grammar rules that cost nothing.

faster-whisper already emits punctuation (it was trained on punctuated data), but quality drops on short segments, noisy audio, and non-English. A dedicated restorer can fix missing/misplaced commas and question marks.

1a. deepmultilingualpunctuation (FullStop) recommended

  • Repo: github.com/oliverguhr/deepmultilingualpunctuation
  • Install: pip install deepmultilingualpunctuation
  • Model: oliverguhr/fullstop-punctuation-multilang-large (BERT-large, ~1.3 GB on disk; a smaller base variant fullstop-punctuation-multilingual-sonar-base exists). Labels: . , ? - :.
  • Languages: English, Italian, French, German, Dutch (community models add 12 more).
  • CPU: Yes, runs on CPU via HuggingFace transformers. Slower than rule-based but sub-second for a sentence.
  • Fit for Mumble: Good as an optional “enhanced punctuation” pass when Whisper’s punctuation is weak. The large model is ~1.3 GB (above the 500 MB preference); the sonar-base variant is smaller. Could be lazy-loaded only when the user enables it, or gated to segments where Whisper produced no punctuation.
  • License: MIT.
Code FullStop API example 
from deepmultilingualpunctuation import PunctuationModel
model = PunctuationModel()
result = model.restore_punctuation("my name is clara and i live in berkeley california")
# -> "My name is Clara, and I live in Berkeley, California."

1b. felflare/bert-restore-punctuation (HuggingFace)

  • Model: huggingface.co/felflare/bert-restore-punctuation
  • Base: BERT-base (~110 M params, ~440 MB). Restores punctuation AND casing.
  • CPU: Yes. Simple transformers pipeline.
  • Languages: English only.
  • Fit: Lighter than FullStop-large, English-only, restores capitalisation too. Good single-language option.

1c. BertPunc / BertPuncCap

  • BertPunc: github.com/nkrnrnk/BertPunc — SOTA punctuation restoration on BERT, research-oriented, less packaged.
  • BertPuncCap: github.com/Anwarvic/BertPuncCap — proof-of-concept restoring punctuation + capitalisation.
  • Fit: More setup work than the pip-installable options; useful as reference implementations if Mumble wants to fine-tune a tiny model on its own dictation style.

1d. whisper-punctuator (zero-shot, reuses the Whisper model)

  • Repo: github.com/jumon/whisper-punctuator
  • Approach: Uses the already-loaded Whisper model’s encoder to insert punctuation via constrained decoding — no extra model download. Works on any Whisper-supported language.
  • Trade-off: Requires the audio file (it’s multimodal: audio + unpunctuated text → punctuated text). Adds a second decoder pass (CPU cost). Limited to 30-second clips.
  • Fit: Interesting because it reuses the Whisper weights Mumble already has — zero added model size. But the extra decode pass on CPU may be too slow for a live dictation app. Better suited to a batch/offline “polish” button.

1e. Rule-based enhancement (no model, zero cost)

Mumble’s current _ensure_terminal only adds a final period. A lightweight rule layer could add:

  • Comma before conjunctions joining independent clauses (... and ... → ..., and ...).
  • Question mark on sentences starting with wh-words (who/what/where/when/why/how/is/are/do/can) when they lack terminal punctuation.
  • Comma after sentence-initial adverbs (however, therefore, meanwhile, ...).

This is free, deterministic, and testable — worth doing regardless of whether an ML model is added.

2Lightweight grammar correction (CPU)

In plain terms

Grammar fixing means turning “this are wrong” into “this is wrong.” The best offline tool (LanguageTool) needs Java installed — a heavy ask for a small app. A pure-Python alternative (Gramformer) exists but is dated and large. The pragmatic answer: add a few grammar rules yourself, and offer the heavier tools as optional add-ons.

2a. language_tool_python (LanguageTool) best quality needs Java

  • Repo: github.com/jxmorris12/language_tool_python (actively maintained, last commit June 2026).
  • Underlying: LanguageTool (Java server, ~200 MB JAR). Non-AI, rule-based grammar/style/spell checker, 30+ languages.
  • Install: pip install language_tool_python (auto-downloads the LanguageTool server JAR on first use; requires Java 17+).
  • CPU: Yes (it’s not even ML). Fast.
  • Fit for Mumble: Excellent quality for grammar/style, supports British English (matches Mumble’s UK-English rule). Drawbacks: requires a JVM dependency (heavy for a lightweight desktop app), the JAR is ~200 MB, and first-run downloads it. Could be an optional plugin for users who want deep grammar checking without cloud AI. GPL-3.0 license — check compatibility with Mumble’s license.
  • License: GPL-3.0.
Code LanguageTool API example 
import language_tool_python
with language_tool_python.LanguageTool("en-GB") as tool:
    matches = tool.check("This are wrong.")
    fixed = tool.correct("This are wrong.")  # -> "This is wrong."

2b. Gramformer (T5-based, pure Python, CPU)

  • Repo: github.com/PrithivirajDamodaran/Gramformer
  • Model: prithivida/grammar_error_correcter_v1 (T5-based seq2seq, ~220 M params, ~850 MB).
  • CPU: Yes — Gramformer(models=1, use_gpu=False). Sentence-level only (trained on 64-token sentences; must chunk longer text).
  • Fit: Purpose-built for ASR post-processing (the README lists “ASR or STT: Speech to text output” as a primary use case). Above the 500 MB preference but the only pure-Python, no-JVM grammar corrector. Works sentence-by-sentence. Caveat: the repo hasn’t been updated since 2022; model is “stable” but not cutting-edge. Note from the author: releases <= v1.0 are NOT for commercial use — verify license terms.
  • License: MIT (code); check model card for the model’s license.
Code Gramformer API example 
from gramformer import Gramformer
gf = Gramformer(models=1, use_gpu=False)
corrected = list(gf.correct("He are moving here.", max_candidates=1))

2c. HappyTransformer / happytransformer

Wraps T5/BERT grammar models with a simpler API. Same underlying models as Gramformer. Useful if a lighter wrapper is wanted, but adds a dependency for little benefit over calling the HF model directly.

2d. Lightweight LLM on CPU (e.g., GGUF-quantised small models)

  • Models like Qwen2.5-0.5B or Llama-3.2-1B (quantised to ~500-700 MB) can do grammar correction via llama.cpp / llama-cpp-python.
  • Fit: Overlaps with Mumble’s existing cloud-AI path; running even a 1 B model on CPU for live dictation is likely too slow (multi-second latency). Not recommended for the live path; could power an explicit “polish” action. Better to keep the cloud AI for this and focus local effort on rules + punctuation models.
Recommendation for grammar: For a lightweight desktop app, prefer enhancing the rule-based layer (subject-verb agreement heuristics, article correction a/an, tense consistency) and offer language_tool_python as an optional module for users who have Java. Gramformer is a fallback if no JVM is acceptable, but it’s heavier than ideal and stale.

3Confidence-based post-processing for Whisper output

In plain terms

Whisper doesn’t just guess words — it also reports how sure it is about each one. Mumble can lean on that “confidence” signal to flag shaky words, drop garbage segments, and decide when to trust a vocabulary correction. The catch: Whisper’s confidence numbers are a bit miscalibrated, so the thresholds need tuning rather than blind trust.

faster-whisper already exposes per-word probabilities (word.prob), and Mumble uses them in annotate_uncertain(). Here are techniques to do more with that signal locally.

3a. Low-confidence word flagging with alternatives (extend current approach)

Mumble already annotates uncertain words with heard//alt. Improvements:

  • Expand the alternative source beyond the mode-mishear map: use the phonetic vocabulary (_phonetic_key) to generate alternatives from the user’s vocabulary list for any low-confidence word, not just mode keywords.
  • Threshold tuning: current threshold is 0.8. Research (arXiv:2502.13446, “Adopting Whisper for Confidence Estimation”) suggests word-level probabilities from Whisper are useful but miscalibrated — a fixed 0.8 may be too aggressive or too lenient depending on model size and language. Consider a per-model or per-language threshold, or use the segment-level avg_logprob and compression_ratio as secondary signals.

3b. Segment-level confidence signals (faster-whisper metadata)

faster-whisper segments expose: avg_logprob, compression_ratio, no_speech_prob. Use these to:

  • Drop/flag segments with no_speech_prob > 0.6 — likely silence that Whisper hallucinated over (see Section 6).
  • Flag segments with compression_ratio > ~2.5 — high repetition / looping risk.
  • Flag segments with very low avg_logprob (e.g., < -1.0) — low confidence; candidate for AI review or re-transcription with a different beam size.

3c. Confidence-weighted vocabulary application

Currently apply_vocabulary_terms applies high-confidence replacements unconditionally. A refinement: only auto-replace a vocabulary term when the original word’s Whisper probability is below a threshold (it was uncertain) AND the phonetic match is strong. High-probability words that happen to phonetically resemble a vocab term should NOT be rewritten (reduces false positives).

3d. N-gram language-model rescoring (lightweight)

  • Use a small KenLM n-gram model (a few MB, pure C++/Python) to rescore the top-K segment hypotheses. faster-whisper’s beam search already does internal scoring, but a domain-specific LM (e.g., trained on the user’s own documents or a medical/legal corpus) can reorder alternatives.
  • Tools: kenlm (pip installable on Windows via wheel), pyctcdecode for beam-search decoding with an external LM.
  • Fit: Lightweight (model is MBs, not GBs), CPU-fast. The main cost is curating/obtaining the LM. For a general dictation app, a generic English KenLM (e.g., from OpenAI’s whisper.cpp project) is a reasonable default. This is the technique used by whisper.cpp and whisper-jax for improved accuracy.

4Python text cleanup / normalisation libraries (lightweight)

In plain terms

These are small, model-free utilities that tidy text: splitting it into proper sentences, repairing garbled characters, and standardising quotes and dashes. They don’t make Mumble smarter — they just stop small messes from reaching the user. A couple are clearly worth adding; the rest are situational.

4a. pySBD — sentence boundary disambiguation recommended

  • Repo: github.com/nipunsadvilkar/pySBD
  • Install: pip install pysbd
  • What: Rule-based sentence segmentation that handles abbreviations, decimals, URLs, etc. — far better than text.split('.').
  • Fit: Useful for splitting a transcript into sentences before passing each to a sentence-level grammar/punctuation model (Gramformer, FullStop). Pure rules, no model, tiny. Recommended.
  • License: MIT.

4b. ftfy — fixes text for you

  • Repo: github.com/rspeer/ftfy
  • Install: pip install ftfy
  • What: Repairs mojibake, broken Unicode, smart-quote issues, control characters. Deterministic, no model.
  • Fit: Cheap insurance for transcripts that occasionally contain corrupted characters (e.g., from audio with unusual encoding). Mumble’s Whisper output is usually clean ASCII, so this is a low-priority safety net.
  • License: MIT.

4c. clean-text

  • Install: pip install clean-text (note: package name is clean-text, import is cleantext).
  • What: Normalises whitespace, quotes, dashes, removes/replaces fancy Unicode. Uses ftfy + unidecode under the hood.
  • Fit: Convenient one-call normalisation for transcript cleanup. Lightweight. Optional dependency on unidecode (GPL) — note the license.
  • License: Apache-2.0 (clean-text itself); unidecode is GPL.

4d. gladiaio/normalization — transcript-specific normaliser

  • Repo: github.com/gladiaio/normalization
  • What: Lightweight library for normalising speech transcripts before computing WER — handles number words, casing, punctuation stripping, etc. Designed specifically for ASR output.
  • Fit: If Mumble ever needs to compare transcripts or evaluate accuracy, this is purpose-built. Otherwise its normalisation is more aggressive than wanted for user-facing text (it strips punctuation for WER). Low priority.
  • License: MIT.

4e. normality

  • Repo: github.com/pudo/normality
  • What: Tiny text-normalisation library (ASCII folding, case folding, whitespace). Minimal.
  • Fit: Overlaps with Mumble’s existing _norm() helper. Not needed unless a more battle-tested normaliser is wanted.

5Filler-word removal & disfluency detection

In plain terms

“Disfluencies” are the ums, false starts, and accidental repeats of natural speech. Mumble already deletes the obvious fillers. The next level is being smarter about where a filler sits (delete it but keep the comma?) and catching false starts like “I went to the, I went to the store.” Plain rules handle this well; full ML disfluency models are too heavy for a CPU-only app.

Mumble already has a regex-based filler remover (_FILLER_RE). Here’s how to improve it.

5a. Expand the filler lexicon

Current regex covers: um/uh/er/ah/erm/hm/mm/mhm/mm-hmm/you know. Consider adding:

  • like (as a filler — tricky: only when used as a discourse marker, not the verb/preposition).
  • you know what I mean, I mean, sort of, kind of, basically, literally, actually, right (tag question), okay so, well so.
  • uh-huh, huh, hmm, mhm, nuh-uh.
  • British: erm, err, hmm, mmm.

5b. Context-aware filler removal

The faster-whisper discussion (#569) highlights the core problem: removing , um, mid-sentence requires deciding whether to delete entirely, replace with a comma, or replace with an em dash. Approaches:

  • Position-based rules:
    • Filler at sentence start → delete (Mumble already does this).
    • Filler between commas (, um,) → delete the filler AND one surrounding comma.
    • Filler before a clause boundary → replace with comma or dash.
  • Confidence-gated: only remove a filler if its word probability is high (Whisper was confident it’s a filler, not part of a real word like “umbrella”).
  • Frequency cap: if fillers appear in > N% of words in a segment, the segment is likely degraded/hallucinated — flag for re-transcription rather than aggressively stripping.

5c. False-start / repetition detection

Whisper often produces “I went to the, I went to the store.” Detect and collapse:

  • N-gram repetition: if a 2-4 word sequence immediately repeats, collapse to one instance (this is the “delooping” technique from the hallucination research — see Section 6).
  • False starts: “I want to — I need to go” → detect the dash/pause and keep the more complete clause (heuristic: longer clause wins, or the one with higher average word probability).

5d. Disfluency-aware models (research, heavier)

End-to-end disfluency removal models exist (e.g., ACL 2020 “End-to-End Speech Recognition and Disfluency Removal”) but require a trained Transformer and are not lightweight enough for Mumble’s CPU-only constraint. The rule-based approach is the right call for now.

6Whisper-specific post-processing: hallucination & repetition

In plain terms

This is the big one. When Whisper hears silence or noise, it sometimes invents text — and it invents the same phrases over and over. A study found that just two phrases (“thank you” and “thanks for watching”) make up about a third of all these phantom outputs. So a short blocklist of known junk phrases, plus a trick to collapse repeated loops, removes Whisper’s most embarrassing mistakes for free. Best of all, you can stop many of them before transcription by trimming silence with a tiny voice-detector.

This is the highest-value local improvement — it’s free (rules/sets), CPU-trivial, and addresses Whisper’s most embarrassing failure mode.

6a. The Bag of Hallucinations (BoH) technique

From arXiv:2501.11378 (“Investigation of Whisper ASR Hallucinations Induced by Non-Speech Audio”, AGH University, 2025):

~35%
of all hallucinations are just two phrases
>50%
come from the top 10 phrases
301K
non-speech inferences studied
  • Whisper produces a small, consistent set of hallucinated phrases on non-speech/silence input. ~35% of all hallucinations are just two phrases (“thank you”, “thanks for watching”); over half come from the top 10.

Top hallucinated phrases (from 301 K non-speech inferences):

Phrase% of hallucinations
thank you24.8%
thanks for watching10.3%
so3.8%
thank you for watching2.6%
the2.5%
you2.2%
oh1.8%
okay0.9%
i’m sorry0.8%
oh my god0.7%
bye0.6%
meow0.5%
subtitles by the amara org community0.5%
subtitles by ...(various)
hello everyone welcome to my channel0.02%
  • Mitigation: build a “Bag of Hallucinations” set. Filter it to remove common English words (the/so/you — too high false-positive risk) and keep the unambiguous ones (“thanks for watching”, “subtitles by the amara org community”, “thank you for watching”, “subscribe to my channel”, etc.). Use the Aho-Corasick multi-pattern string search to detect and strip these from transcripts.
  • Free open-source BoH list: github.com/DSP-AGH/ICASSP2025_Whisper_Hallucination (the paper’s repo includes the hallucination list + BoH).
  • A Reddit community (r/LocalLLaMA, March 2026) collected 135 hallucinated phrases from production meeting-bot audio — a good real-world supplement to the academic list.
  • Fit for Mumble: Extremely high value, zero model cost. Add a curated hallucination-phrase blocklist, applied post-transcription. Gate on no_speech_prob or low avg_logprob to avoid false positives (don’t strip “thank you” from genuine speech).

6b. Delooping (repetition collapse)

From the same paper and the OpenAI Whisper discussions:

  • Looping = immediate repetition of a previous fragment (“Welcome to New York City of New York City of New York...”). Appears in ~9-20% of hallucinations.
  • Detection: find the longest repeated suffix/prefix pattern. A simple algorithm: for each segment, check if the last N words equal the preceding N words (for N = 2..8); if so, keep one copy. Also detect repeated phrases (3-6 word blocks) anywhere in the segment.
  • Fit: Already partially relevant to Mumble’s live dictation (short clips are less prone to looping, but it can still happen on a held key with background noise). Cheap to add.
Code Delooping regex 
# Detects a phrase repeated 3+ times; collapse to one. Tune the length window.
re.compile(r'\b(.{2,40}?)\b(?:\s+\1\b){2,}')

6c. VAD pre-filtering (prevent hallucinations at the source)

  • The ICASSP paper shows SileroVAD is the single most effective hallucination reducer (WER dropped from ~105% to ~8% on augmented speech). SileroVAD is tiny (~2 MB), CPU-fast, and has a Python API.
  • Fit: If Mumble doesn’t already use VAD before Whisper, adding SileroVAD to trim silence/noise before transcription would dramatically cut hallucinations before post-processing. This is a pre-processing win, not post-processing, but worth flagging. Mumble should verify whether its current audio-capture pipeline already gates on voice activity.
  • Repo: github.com/snakers4/silero-vad

6d. Hallucination silence threshold & beam size (faster-whisper params)

  • faster-whisper’s hallucination_silence_threshold (skips silence longer than N seconds) reduces hallucinations on long audio. Set appropriately for Mumble’s clip length.
  • beam_size: the paper found beam size 1 vs default made little difference for hallucinations; don’t rely on it.
  • compression_ratio_threshold and log_prob_threshold: faster-whisper can auto-retry or drop segments exceeding these — ensure Mumble sets sensible values.

6e. Known Whisper-specific text artefacts to clean

  • “Subtitles by...” / “Subtitles by the Amara.org community” → strip (these are training-data artefacts leaked into output).
  • “Transcript: ...” prefixes → strip.
  • Repeated single-letter tokens (“a a a a”) → collapse.
  • Trailing “...” on a segment that should be complete → replace with period.

7Summary: recommended implementation priorities

In plain terms

Here’s the to-do list, ordered by bang-for-buck. The top five items cost nothing — no models, no downloads — and deliver most of the quality gain. The ML models and Java tools sit lower down as opt-in extras. If you do only one thing, do item 1: kill the phantom phrases.

Ranked by value-to-effort ratio for Mumble’s lightweight, CPU-only, no-network constraint:

PriorityTechniqueCostEffortExpected impact
1 (do first)Hallucination phrase blocklist (BoH) + delooping0 (rules/sets)LowEliminates the most embarrassing Whisper failures
2Segment-level confidence gating (no_speech_prob, compression_ratio, avg_logprob)0LowFlags/drops bad segments before they reach the user
3Expanded rule-based punctuation (commas, question marks, adverb commas)0LowVisible quality lift on the offline path
4Expanded filler lexicon + context-aware removal0MediumCleaner transcripts, fewer false strips
5False-start / n-gram repetition collapse0MediumHandles disfluencies the regex misses
6pySBD for sentence segmentation (pre-step for any sentence-level model)~tiny depLowEnables better sentence-level processing
7Confidence-weighted vocabulary application0MediumFewer false-positive vocab rewrites
8deepmultilingualpunctuation (optional, lazy-loaded)~1.3 GB modelMediumML punctuation when rules aren’t enough
9SileroVAD pre-filtering (if not already present)~2 MBMediumPrevents hallucinations at source
10language_tool_python (optional plugin, needs Java)~200 MB JAR + JVMMediumDeep grammar checking without cloud

Key principle: the free, rule-based techniques (1-5, 7) deliver most of the quality gain at zero model cost and should be the foundation. ML-based punctuation/grammar (8, 10) are optional enhancements for users who opt in and can afford the disk/CPU cost. The hallucination and confidence work (1, 2, 9) is where Whisper’s known failure modes are — that’s the highest-leverage local improvement.
