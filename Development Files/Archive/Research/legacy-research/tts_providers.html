Research

TTS Providers

◆Research date: 2026-06-23
◆Purpose: Inform a multi-provider TTS architecture for the Mumble desktop app
◆Current path: OpenRouter TTS
In plain terms

This document is a shopping guide for text-to-speech (TTS) services — the cloud APIs that turn written text into spoken audio. Mumble currently speaks through one provider (OpenRouter), and the goal is to support several so we can pick the best male voices, keep quality high, keep it fast, and show progress while audio is generated.

Below, each provider gets its own section: what voices it has (especially male ones), how you connect to it, what audio it returns, how fast it is, what it costs, and any free allowance. A big side-by-side comparison table and concrete architecture recommendations are at the end. Nothing in the original research has been left out — the dense developer bits (code, exact voice-id lists) are tucked into collapsible panels so the overview stays readable.

Goals driving this research: provider expansion, male-voice priority, expose only high-quality voices, cross-provider consistency, low latency, and progress feedback.

This report covers the major TTS APIs available in 2026, with per-provider notes on male voices, API/auth, response formats, latency, pricing, free tiers, and Python/HTTP integration. A consolidated comparison table and architecture recommendations are at the end.

1OpenRouter TTS (current provider)

In plain terms

OpenRouter is a middleman. Instead of signing up with ten different voice companies, you talk to OpenRouter's single endpoint and it forwards your request to whichever underlying model you name (Google, OpenAI, xAI, Mistral, and more). One key, one API shape, many voices behind it. This is what Mumble uses today.

OpenRouter is an aggregator that exposes a single OpenAI-compatible TTS endpoint and routes to many underlying providers. This is the app's current path.

Endpoint & auth

  • POST https://openrouter.ai/api/v1/audio/speech
  • OpenAI Audio Speech API-compatible (same request/response shape).
  • Auth: Bearer token, header Authorization: Bearer $OPENROUTER_API_KEY.
  • Discover TTS models via GET https://openrouter.ai/api/v1/models?output_modalities=speech.

Request parameters

ParameterRequiredNotes
modelYesProvider-prefixed slug, e.g. openai/gpt-4o-mini-tts-2025-12-15
inputYesText to synthesize
voiceYesVoice id; varies per model
response_formatNomp3 or pcm (default pcm)
speedNoMultiplier; only honored by some providers (e.g. OpenAI). Default 1.0
providerNoProvider-specific passthrough options (e.g. Azure style/styledegree, OpenAI instructions)

Response

  • Raw audio byte stream (NOT JSON). Non-200 returns JSON error body.
  • Content-Type: audio/mpeg (mp3) or audio/pcm (pcm).
  • Header X-Generation-Id for tracking.

Pricing model

  • Per-character of input text (for character-billed models) or per token (token-billed models). Check each model page on OpenRouter for exact per-character cost.

Python integration

Fully OpenAI-SDK compatible. Point the OpenAI client at OpenRouter's base URL.

Code Python — OpenRouter via OpenAI SDK 
from openai import OpenAI
client = OpenAI(base_url="https://openrouter.ai/api/v1", api_key="<OR_KEY>")
with client.audio.speech.with_streaming_response.create(
    model="openai/gpt-4o-mini-tts-2025-12-15",
    input="Hello world.", voice="onyx", response_format="mp3",
) as r:
    r.stream_to_file("out.mp3")

Male-voice notes

  • openai/gpt-4o-mini-tts-* voices: male-leaning = onyx, ash, echo, sage, ballad, cedar, marin.
  • microsoft/mai-voice-2 exposes Azure voice names, e.g. en-US-Guy:MAI-Voice-2, en-US-Davis:MAI-Voice-2, en-US-Andrew:MAI-Voice-2.
  • x-ai/grok-voice-tts-1.0 male voices: Rex, Leo (Eve/Ara/Sal are female-coded).

Free tier

None directly from OpenRouter (you pay the underlying provider cost + OpenRouter margin). A small credit may be available on signup depending on account/promos.

Latency

Aggregator overhead on top of the underlying provider. PCM streaming recommended for real-time pipelines. Token-billed models like Gemini Flash TTS and Grok Voice TTS are fast; MAI-Voice-2 and Voxtral are heavier.

2Google Cloud TTS / Google AI TTS

In plain terms

Google offers two related voice products. The older Cloud Text-to-Speech charges by the character and has many quality tiers (from cheap-and-robotic to premium "Journey" voices). The newer Gemini-TTS charges by token, streams audio, and is faster. Google's standout perk is a generous ongoing free allowance — more sustained free usage than most rivals.

Two related products: classic Cloud Text-to-Speech (per-character) and newer Gemini-TTS (per-token, via Vertex AI / Gemini API).

Endpoint & auth

  • Cloud TTS: POST https://texttospeech.googleapis.com/v1/text:synthesize (REST); also speech.googleapis.com for streaming.
  • Gemini TTS: Gemini API generateContent with audio output modality, or Vertex AI.
  • Auth: Google service-account JSON or API key (Cloud TTS accepts API key for many operations); OAuth2 access token for Vertex.

Response formats

  • Cloud TTS: returns base64-encoded audio in audioContent. Supported encodings: MP3, LINEAR16 (WAV PCM), OGG_OPUS, MULAW, ALAW. Sample rates up to 24000 Hz for most voices.
  • Gemini TTS: PCM 24kHz/16-bit mono, watermarked with SynthID.

Notable male voices (en-US)

  • Neural2: en-US-Neural2-D (male), also -I, -J variants.
  • WaveNet: en-US-Wavenet-D, -I, -J.
  • Studio/Journey: en-US-Journey-D (male, premium).
  • Chirp 3 HD: named voices; check the voice list endpoint for current male options.
  • Standard (avoid for quality): en-US-Standard-B, -D.

Latency

  • Cloud TTS (Neural2/Chirp3): request-response only, ~400-600ms TTFAB, no streaming.
  • Gemini TTS: streams; lower latency, suitable for real-time.

Python integration

  • Official client library: pip install google-cloud-texttospeech.
  • Gemini TTS via google-genai SDK (pip install google-genai).
Code Python — Google Cloud TTS 
from google.cloud import texttospeech
client = texttospeech.TextToSpeechClient()
resp = client.synthesize_speech(
    input=texttospeech.SynthesisInputText(text="Hello."),
    voice=texttospeech.VoiceSelectionParams(language_code="en-US", name="en-US-Neural2-D"),
    audio_config=texttospeech.AudioConfig(audio_encoding=texttospeech.AudioEncoding.MP3),
)
open("out.mp3","wb").write(resp.audio_content)

Free tier

Strong ongoing free tiers (see table above). Best sustained free allowance among cloud providers for WaveNet/Neural2 (1M chars/mo) and Standard (4M chars/mo).

3ElevenLabs

In plain terms

ElevenLabs is the quality benchmark everyone compares against. The voices sound the most human, it has a deep catalog of named male voices plus a huge community library, and it can clone a voice. The trade-off is price: it sells subscription "credit" plans rather than simple per-character billing, and at scale it is one of the pricier options.

Widely regarded as the quality reference for managed TTS in 2026. Premium price, premium output, strong male-voice catalog and voice cloning.

Endpoint & auth

  • REST: POST https://api.elevenlabs.io/v1/text-to-speech/{voice_id} (with ?output_format=mp3_44100_128 etc.).
  • Streaming variant: /v1/text-to-speech/{voice_id}/stream.
  • WebSocket streaming endpoint also available for real-time.
  • Auth: xi-api-key header (or Authorization: Bearer).

Models

  • eleven_v3 (alpha/premium) - highest expressiveness, multilingual.
  • eleven_multilingual_v2 - 32 languages.
  • eleven_turbo_v2.5 - fast, multilingual, good quality/latency balance.
  • eleven_flash_v2.5 - lowest latency.
  • Legacy eleven_mono_v1 (deprecated path).

Pricing (subscription, credits)

Response formats

mp3_44100_128 (default), mp3_44100_192, pcm_44100 (Pro+), pcm_24000, ulaw_8000 (telephony), opus_48000_32, opus_48000_64.

Latency

Turbo v2.5 streaming ~200-300ms TTFAB. Flash lower. Business plan advertises low-latency TTS as low as 5c/minute.

  • Antoni - smooth, conversational

  • Josh - young, energetic
  • Sam - raspy, conversational
  • Michael - news/announcer
  • George - calm storyteller
  • Giovanni - Italian-accented male

Use GET /v1/voices to enumerate; filter by labels.gender == "male". The community library exposes thousands of additional male voices (each with a voice_id).

4Azure Cognitive Services / AI Speech TTS

In plain terms

Azure has the biggest voice catalog of anyone — 500+ voices across 140+ locales — with lots of male options, plus the most generous ongoing free tier (500K characters every month, forever). It is also the engine behind OpenRouter's MAI-Voice-2. Requests are written as SSML (a markup format for controlling speech), and its SDK can emit progress events while audio is being made — handy for showing a progress bar.

Broadest voice catalog of any provider (500+ voices, 140+ locales) with strong male coverage and excellent ongoing free tier. Also the backend for OpenRouter's microsoft/mai-voice-2.

Endpoint & auth

  • REST: POST https://{region}.tts.speech.microsoft.com/cognitiveservices/v1 (body = SSML document).
  • Streaming/low-latency: WebSocket and the Speech SDK.
  • Auth: Authorization: Bearer <token> (token from Speech resource key) or Ocp-Apim-Subscription-Key: <key> header.
  • LiteLLM and Azure AI Foundry also expose a chat-style interface.

Code Python — Azure Speech SDK 
import azure.cognitiveservices.speech as speechsdk
cfg = speechsdk.SpeechConfig(subscription="<key>", region="<region>")
cfg.speech_synthesis_voice_name = "en-US-DavisNeural"
cfg.set_speech_synthesis_output_format(
    speechsdk.SpeechSynthesisOutputFormat.Audio16Khz32KBitRateMonoMp3)
synth = speechsdk.SpeechSynthesizer(cfg, None)
result = synth.speak_text("Hello world.")
open("out.mp3","wb").write(result.audio_data)

The Speech SDK emits synthesizing events with audio chunks (good for progress feedback) and viseme_received/bookmark_reached events.

5OpenAI TTS

In plain terms

OpenAI has the simplest API of the bunch. Its newest model, gpt-4o-mini-tts, lets you give plain-English instructions ("speak in a calm, deep baritone") to control accent, emotion, and speed, and it streams. Good voices, fast, cheap — but only a small trial credit, no ongoing free tier.

Simplest API. Newer gpt-4o-mini-tts supports style instructions and streaming.

Endpoint & auth

  • POST https://api.openai.com/v1/audio/speech
  • Auth: Authorization: Bearer $OPENAI_API_KEY.

Models

ModelPrice/1M charsStreamingNotes
gpt-4o-mini-tts$15YesNewest; supports instructions for accent/emotion/speed
tts-1$15YesOlder architecture, slightly more robotic
tts-1-hd$30NoHigher quality, batch use
gpt-4o-voicecontact salesYesRealtime API product (separate scope)

Max input ~2000 tokens for gpt-4o-mini-tts.

Voices (13, gpt-4o-mini-tts)

alloy, ash, ballad, coral, echo, fable, nova, onyx, sage, shimmer, verse, marin, cedar.

  • Recommended for quality: marin, cedar.
  • Male-coded: onyx (deep), ash, echo, sage, ballad, cedar, marin.
  • Female-coded: coral, nova, shimmer, fable, alloy, verse.
  • tts-1/tts-1-hd support a smaller set: alloy, ash, coral, echo, fable, onyx, nova, sage, shimmer.

Response formats

mp3 (default), opus, aac, flac, wav, pcm (24kHz 16-bit signed LE, no header). For lowest latency use wav or pcm.

Latency

~250-350ms TTFAB for gpt-4o-mini-tts streaming. tts-1 ~300-500ms.

Custom voices

Available to eligible orgs (contact sales): create a voice from a consented sample, then pass voice: {id: "voice_..."}. Up to 20 voices/org.

Python SDK

) as r:
    r.stream_to_file("out.mp3")

Free tier

~$5 trial credit (shared across all OpenAI APIs, 3 months). No ongoing free tier.

6Other notable TTS providers

In plain terms

Beyond the big five, there's a long tail of specialists: Cartesia (the fastest), Deepgram (cheap, generous credit, many male voices), PlayHT (huge catalog), Hume (emotional acting), Amazon Polly (steady AWS option), and a few cloning/enterprise/open-source choices. Each fills a niche — pick by what matters most for a given use.

6a. Cartesia (Sonic)

  • Product: Sonic-3.5 (latest), purpose-built for low-latency realtime TTS.
  • Endpoint: POST https://api.cartesia.ai/tts/bytes (REST) and WebSocket wss://api.cartesia.ai/tts/websocket for streaming.
  • Auth: Authorization: Bearer + Cartesia-Version header; API key from dashboard.
  • Voices: built-in palette + instant voice cloning from short audio; 40+ languages.
  • Latency: ~80-90ms TTFAB (streaming) - the latency leader.
  • Pricing: pay-as-you-go ~$50/1M chars. Free: $5 credit (~100K chars). Subscriptions: Free (20K credits), Pro $5, Startup $49, Scale $299.
  • Formats: PCM, MP3, raw 24kHz/16-bit. Streams chunked.
  • Python: official cartesia SDK (pip install cartesia).

6b. Deepgram (Aura-2)

  • Product: Aura-2 enterprise streaming TTS; pairs with Nova-3 STT.
  • Endpoint: POST https://api.deepgram.com/v1/speak?model=aura-2-<voice>-<lang> and WebSocket streaming.
  • Auth: Authorization: Token <DEEPGRAM_API_KEY>.
  • Voices (en, masculine): aura-2-apollo-en, aura-2-arcas-en, aura-2-aries-en, aura-2-atlas-en, aura-2-draco-en (British), aura-2-hermes-en, aura-2-hyperion-en (Australian), aura-2-jupiter-en, aura-2-mars-en, aura-2-neptune-en, aura-2-odysseus-en, aura-2-orion-en, aura-2-orpheus-en, aura-2-pluto-en, aura-2-saturn-en, aura-2-zeus-en. Also Aura-1: aura-orion-en, aura-arcas-en, aura-perseus-en, aura-angus-en (Irish), aura-orpheus-en, aura-helios-en (British), aura-zeus-en.
  • Latency: ~120-150ms TTFAB.
  • Pricing: ~$15/1M chars. Free: $200 signup credit (~13M chars).
  • Languages: English (US/GB/AU/IE/PH), Spanish, German, French, Dutch, Italian, Japanese.
  • Formats: WAV/PCM/MP3 via output params; streaming chunked.
  • Python: pip install deepgram-sdk.

6c. PlayHT

  • Product: PlayHT 2.0 Turbo; large voice catalog (900+ voices, 142 languages).
  • Endpoint: REST https://api.play.ht/api/v2/tts/stream + WebSocket.
  • Auth: X-USER-ID + Authorization: Bearer <SECRET_KEY> (or API key header).
  • Voices: extensive library with many male voices; instant cloning from 3-10s clip (Creator+), "Ultra" high-fidelity cloning (Pro+).
  • Latency: ~300-500ms TTFAB (Turbo).
  • Pricing: Free 12,500 chars/mo; Creator ~$33/1M at quota; Pro ~$22/1M at quota.
  • Python: pip install pyht (official SDK, streaming-first).

6d. Hume AI (Octave)

  • Product: Octave TTS - emotionally expressive; prompted with natural-language emotional direction instead of SSML.
  • Endpoint: https://api.hume.ai/v0/tts (REST + streaming).
  • Auth: Bearer API key.
  • Pricing: ~$30/1M chars; $5 signup credit.
  • Voices: built-in palette, no cloning; English only.
  • Best for: character/dialogue where emotional authenticity matters.

6e. Amazon Polly

  • Voices: fixed catalog, no cloning. Male en-US: Matthew, Brian, Justin, Kevin, Stephen (Neural); Joey, Matthew (Generative).
  • Endpoint: https://polly.<region>.amazonaws.com/v1/speech.
  • Auth: AWS SigV4 (IAM).
  • Pricing: Standard $4, Neural $16, Generative $30, Long-form $100 per 1M chars. Free: 5M Standard + 1M Neural for first 12 months only.
  • Formats: mp3, ogg_vorbis, pcm, json (speech marks).

6f. Resemble.ai

  • Per-second pricing (~$0.006/s ~ $21.60/hr ~ $7.94/1M chars). Voice cloning self-serve. Good for narration. Endpoint https://app.resemble.ai/api/v2/tts.

6g. WellSaid Labs

  • Enterprise narration (L&D, marketing). Maker $49/mo. Legally vetted voice avatars. Contact sales for API at scale. No self-serve cloning.

6h. Self-hosted / open source

  • Coqui xTTS v2 (company shut down, code archived): 17 languages, clone from 3-6s clip, MPL-2.0 weights (review commercial licensing). Effectively $0 API cost, pay for GPU compute (~$0.25-0.50/hr audio on A10G).
  • Kokoro 82M (open-weight, also on OpenRouter): 8 languages, 54 preset voices.
  • Orpheus 3B (Canopy Labs, open-weight): English, 7 preset voices; on OpenRouter.
  • Sesame CSM 1B (open-weight): conversational English; on OpenRouter.
  • Zyphra Zonos v0.1 (open-weight): US/UK English, male+female; on OpenRouter.

8Recommendations for Mumble's multi-provider architecture

In plain terms

This section is the actionable plan. The core idea: build one common interface for "speak this text" and write a small adapter per provider behind it, so the rest of the app never cares which company made the audio. Then the recommendations cover which providers to add first, how to put male voices front-and-center, how to hide low-quality voices, how to keep everything consistent across providers, how to stay fast and show progress, where to keep the secret keys, and what open questions still need an answer.

8.1 Provider expansion (abstraction layer)

Define a single TTSProvider interface and one adapter per backend. OpenRouter is itself an aggregator, so treat it as one provider that fans out to model slugs. Native adapters (OpenAI, ElevenLabs, Azure, Google, Cartesia, Deepgram) give better control of provider-specific features (Azure SSML styles, OpenAI instructions, ElevenLabs voice settings) than going through OpenRouter for everything.

Suggested core providers to support first (best quality + male-voice coverage + latency):

1
OpenAI (gpt-4o-mini-tts)

Keep as a default; cheap, fast, instructions.

2
Azure AI Speech

Best free tier, huge male catalog, SSML, streaming events.

3
ElevenLabs

Premium quality + cloning for power users; male voice priority.

4
Cartesia Sonic

Lowest latency for real-time; cloning.

5
Google Cloud TTS / Gemini TTS

Broad language coverage, generous free tier.

6
OpenRouter (existing)

Keep as fallback/aggregator for niche models (Grok Voice, Voxtral, Kokoro, etc.).

8.2 Male-voice priority

Each adapter should ship a curated MALE_VOICES allowlist with stable aliases mapped to provider-specific ids, e.g.:

Map Persona alias → provider voice ids 
male_deep      -> openai:onyx | azure:en-US-GuyNeural | eleven:Daniel | cartesia:<id>
male_narrator  -> openai:cedar | azure:en-US-Davis:DragonHDLatestNeural | eleven:Adam
male_warm      -> openai:echo | azure:en-US-DavisNeural | eleven:Antoni
male_young     -> openai:ash | azure:en-US-JasonNeural | eleven:Josh

Surface male voices first in the UI; filter the provider's voice list by gender where the API exposes labels (ElevenLabs labels.gender, Deepgram expressed_gender, Azure voice metadata). For providers without gender metadata (OpenAI, Google), hardcode the known male ids.

8.3 Expose only high-quality voices

  • Per provider, maintain an allowlist of vetted high-quality voices; hide Standard/legacy.
    • Google: only Neural2 / Chirp3-HD / Journey / Gemini-TTS (skip Standard).
    • Azure: prefer Dragon HD and MultilingualNeural voices; skip older non-neural.
    • OpenAI: only gpt-4o-mini-tts voices (skip tts-1 where possible).
    • ElevenLabs: only Turbo v2.5 / v3 models with curated default voices + a small set of verified library voices.
  • A quality gate (e.g. minimum sample-rate 24kHz, neural-only) in the adapter base class.

8.4 Cross-provider consistency

  • Normalize output to a single delivery format internally (recommend 24kHz 16-bit PCM or 44.1kHz MP3) so the player layer is provider-agnostic.
  • Map a small set of abstract voice personas (deep, narrator, warm, young, calm) across providers (as above) so a user's chosen persona survives provider switches.
  • Normalize speed (0.5-2.0 where supported; ignore where not).
  • Normalize error reporting (provider-specific -> common error codes for retry/fallback).

8.5 Low latency + progress feedback

  • Prefer streaming endpoints (chunked transfer) for all providers that support it.
  • Emit incremental progress (bytes received / approx. duration) to the UI.
  • For Azure, use the Speech SDK's synthesizing/bookmark_reached events for fine-grained progress; for OpenAI/ElevenLabs use the streaming generators and forward chunk counts.
  • PCM output for the lowest decode latency; transcode to MP3 only if persistence needed.
  • Provider fallback chain: if primary provider errors or times out (>N ms TTFAB), fall back to next provider with the same persona mapping.

8.6 Auth & secrets

  • Store provider API keys in the app's existing secrets mechanism (do not hardcode).
  • One key per provider; OpenRouter key covers its sub-models.
  • For Google/Azure, support both API-key (where available) and service-account/resource key flows.

8.7 Open questions / follow-ups

  • Confirm which provider(s) the owner wants as paid defaults vs. BYO-key.
  • Decide whether to expose voice cloning (ElevenLabs/Cartesia/PlayHT/Resemble) or preset-only for v1.
  • Confirm target languages (English-only vs. multi-language) - affects whether Google/Azure/Polyglot/Gemini-TTS multilingual wins matter.
  • Verify ElevenLabs default voice IDs at integration time (they rotate); cache the /v1/voices response.
