03

Current source reality

These improvements exist in current source and the rebuilt 0.9.1 archive, but are not yet fully verified as a public release.

Dictation repair present

formatting.sanitize_hotwords() is restored, closing the known pre-Whisper failure in canonical local STT source.

Meeting durability improved

Capture journals its UUID WAV before the microphone starts, writes private audio incrementally, repairs canonical headers after hard exit, resumes pending work at boot and refreshes the open Meetings view as recovery advances.

Settings routes made explicit

Overview, Transcription and Processing show requested versus effective routes, no-key/provider fallback and whether audio or transcript text can leave the device.

False success closed at the bridge

History, clipboard, favourites, presets and settings now wait for durable backend success before the Windows UI removes data or reports completion.

Persistence hardened

Settings validate loads and writes, preserve legacy/future values, recover visibly and merge top-level plus nested edits without stale-writer resurrection.

Windows gate authoritative

The isolated runner completed 69/69 offline scripts in 355.1 seconds. Critical lint, compilation, JavaScript syntax, high-severity source scanning and pinned dependency auditing are clean.

Workspace presentation consolidated

Home no longer wastes space on duplicate live state or an empty grid gap; Deck and Meetings use the warm glass system; Stats opens with a screenshot-ready cross-product snapshot.

Search route made independent

Search starts as its own compact app-first window, shows native icons without exposing indexed targets, stays warm when hidden and coexists with a lazily-created full workspace in either startup order.

i

Verification boundary

Home, Deck, Stats, Meetings and both Search/main startup orders were exercised in native Windows WebView2, and the 0.9.1 archive passed its manifest checks. That does not prove the physical global hook, microphone behavior or clean installation; those remain separate release gates.

05

Ordered remediation plan

Work in vertical slices. Do not reopen feature breadth until the first three waves are green.

Stabilise the checked-out repairs

Add targeted tests for hotwords/local STT, meeting durability/deletion/pause, settings concurrency, privacy copy and disabled update behaviour. Resolve any regression before further work.

Keep the isolated test baseline green

Use the runner as the Windows entry point, retain per-test timeouts and explicit live opt-in, and preserve machine-readable results in CI.

Prove installation reproducibility

Install the new exact runtime set into an empty environment, resolve any platform conflict, run import/feature gates and convert successful resolution into verified platform constraints.

Close privacy and product contradictions

Finish Reader disclosures, settle Smart Mode instructions, correct the user guide and keep unavailable service surfaces hidden.

Build release and trust infrastructure

CI, artifact manifest, signed binaries, owner-provisioned publisher key, signed feed and clean archive verification.

Converge platforms and architecture

Shared core + shared Web UI + explicit OS adapters, followed by native platform qualification and incremental controller extraction.

07

How to update this page

Status changes only when evidence changes.

  • Mark implemented only when the path is reachable in current source.
  • Mark verified only when the production path or equivalent behavioural seam ran successfully.
  • Mark shipped only when the tested artifact contains the change.
  • Never copy a completed session into STATUS; move it to a one-line LOG entry.
  • Never keep closed blockers for historical colour.
  • Never infer parity from copied files or successful Python compilation alone.
✓

Exit condition for version 1.0

All blocker rows are closed with direct evidence, a fresh signed artifact passes clean install/run/update/uninstall validation, and the supported platform claim matches native results.
