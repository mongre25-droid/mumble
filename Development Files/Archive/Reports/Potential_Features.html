Long-term feature garden

Mumble — Potential Features Catalogue

◆Scope: useful features and capabilities that could extend Mumble beyond the current v0.9 codebase and the official V1.0–V1.4 roadmap.
◆Status: idea catalogue — not a committed roadmap.
◆Source: derived from Internal/app/, the core docs, and the current UX spec.
◆Last updated: 2026-07-08
In plain terms

This document is a place to park feature ideas without letting them scatter across chat logs or private notes. Every entry is grounded in Mumble's existing architecture or user value. The goal is to keep the list honest: no fake capabilities, no features that contradict the local-first, privacy-first stance unless the trade-off is explicitly flagged.

The official roadmap already covers local AI post-processing, platform acceleration, meeting intelligence, and a custom Mumble model. The entries below are complementary: they are things that could be added after (or alongside) that roadmap, or that extend features already present in the codebase.

Legend

High impact — a standout capability that would materially change how users experience Mumble.

Quick win — small surface area, mostly reusing existing code paths.

Builds on existing — extends a module that already exists (e.g. Deck, Reader, meeting_store, local_engine).

Heavy / owner call — large architectural work, significant compute, or a product decision that needs the owner.

1Dictation loop & input

These ideas change the moment-to-moment dictation experience: how you start, stop, correct, and control Mumble with your voice.

FeatureWhat it would doWhy it mattersStatus
Pre-paste preview bubble Show the shaped text for 1–2 seconds before pasting, with quick actions to edit, re-run, or undo. Reduces the cost of a mis-transcription without breaking the zero-friction loop. Reuses the existing island overlay and hint system. High impact Builds on existing
Spoken punctuation & formatting commands Recognise commands like "new line", "comma", "delete last word", "capitalize that" inside dictation and apply them locally. Keeps hands off the keyboard for longer; fits naturally into the local formatting pipeline. Quick win Builds on existing
Spoken mode switching Phrases like "make it an email" or "turn this into a prompt" switch the active mode mid-utterance. Matches the "infer, don't configure" philosophy; reduces UI interaction. High impact Builds on existing
Real-time partial transcript in the island Stream the 5-second chunk transcriptions into the island as you speak, so you can abort early if the text is wrong. Catches errors before the AI pass and paste step; uses the existing _stream_worker. Builds on existing
Per-app output profiles Detect the foreground window and bias the output: Outlook gets email formatting, Slack gets short chat, VS Code gets a code comment. Delivers on "infer, don't configure" at the OS level; only needs the window class/title, not its content. High impact
Multi-language auto-detection & code-switching Detect the spoken language per utterance and load the right Whisper model; tolerate mid-sentence language switches. Essential for multilingual users; currently the language is a single global setting. High impact Heavy / owner call
Continuous dictation mode An optional hands-free mode where Mumble listens continuously and segments utterances by silence, rather than push-to-talk. Useful for long-form writing sessions; can be done locally with the existing VAD path. Builds on existing
Voice-activated undo / redo Say "undo that" or "redo that" to revert or re-apply the last paste without touching the keyboard. Closes the error-recovery loop for hands-free workflows. Quick win
Adjustable pre-roll buffer Keep a rolling 1–2 second audio buffer before the hotkey press, so words spoken just before pressing are not clipped. Solves the common "first word cut off" problem; small audio pipeline change. Quick win
Local audio replay per dictation Optionally save the raw audio of each dictation (local-only, encrypted) so the user can replay it to resolve a transcription dispute. Helps users improve accuracy over time; must be strictly opt-in because it changes the privacy promise. Heavy / owner call

2Output shaping & smart modes

Ideas for making the Text / Prompt / Email / Reply / Foreign modes smarter and more controllable.

FeatureWhat it would doWhy it mattersStatus
"Translate" mode Translate the dictated text into another language, not just repair foreign terms. Natural extension of Foreign mode; cloud or local LLM can handle it. Builds on existing
User style examples Let the user paste a sample of their own writing and ask Mumble to "make it sound like this". Gives consistent personal voice across AI-shaped output; can be added as a custom preset field. Builds on existing
Per-mode preview before paste Show a side-by-side or inline preview of what Email mode vs Text mode will produce before choosing one. Reduces mode mistakes, especially when the auto-detection is uncertain. Quick win
Tone & audience presets Quick selectors like "Executive summary", "Friendly colleague", "Formal client", "Plain English" that feed the prompt preferences. Makes prompt preferences less abstract and faster to switch. Builds on existing
Output length target Spoken length constraints: "in 50 words", "one paragraph", "three bullets". Common user intent; easy to inject into the prompt constitution. Quick win
Custom snippet / template expansion User-defined voice triggers like "insert signature" or "insert standup" that paste a templated block of text. Complements the Deck presets by adding direct dictation shortcuts. Quick win
Multi-step prompt chaining For complex Prompt-mode requests, let the user chain follow-ups ("now make it shorter", "add a risk section") within one session. Builds on the existing prompt memory window; turns Mumble into a lightweight writing companion. Builds on existing
Inline editing mode Dictate edits to existing text: "make this shorter", "add a joke", "rewrite the second paragraph". Extends the Deck "Improve" preset into a live dictation interaction. Builds on existing

3Accuracy, adaptation & audio quality

Features that make Mumble more accurate for individuals, noisy environments, and specialised vocabulary.

FeatureWhat it would doWhy it mattersStatus
Adaptive vocabulary & correction learning When the user corrects a word, Mumble learns the correction and updates its phonetic vocabulary and STT hotwords. Closed feedback loop for names, jargon, and accents; leverages foreign_boost.py and settings vocabulary. High impact Builds on existing
Personal name / jargon import Import contacts, email signatures, or a custom word list to seed the vocabulary before first use. Big accuracy win for professionals with domain-specific language. Quick win
Domain-specific language packs Optional add-on vocabularies for medicine, law, software, finance, etc. Broadens Mumble's accuracy without requiring every user to maintain their own list. Builds on existing
rpunct punctuation restoration Run a small BERT model locally to restore punctuation before the cloud or local LLM pass. Architecture review already identified this as a near-optimal local stage; improves offline quality. High impact Heavy / owner call
GRMR grammar correction Add a 2B-parameter grammar model as an optional local post-processing stage. Part of the multi-stage local pipeline planned for local-only users. Heavy / owner call
DeepFilterNet3 noise suppression Pre-process mic audio with AI noise suppression before sending it to Whisper. Architecture review flagged this as a latency/accuracy spike; useful for open-plan offices and headsets. Heavy / owner call
Auto gain control & normalisation Normalise input volume and peak levels so quiet voices and distant mics perform consistently. Simple audio pre-processing that improves transcription accuracy across devices. Quick win
Bluetooth / wireless headset profiles Detect headset characteristics and adjust VAD, sample handling, and latency accordingly. Bluetooth mics behave differently from wired mics; a profile system reduces friction. Builds on existing
Model quality A/B comparison UI Let the user compare two transcription or post-processing models on the same audio clip to pick the best for their voice. Turns model selection from guesswork into an evidence-based choice. Heavy / owner call

4The Deck & knowledge management

The Deck is already a powerful history/clipboard/prompt surface. These ideas turn it into a long-term knowledge tool.

FeatureWhat it would doWhy it mattersStatus
Semantic search Index Deck, History, Meetings, and Reader with a local embedding model so users can search by meaning. Already deferred for embedding-store reasons, but it is the single biggest unlock for the Deck as a knowledge base. High impact Heavy / owner call
Auto-tagging by topic Automatically tag transcripts with topics (work, personal, project names) using local keyword/topic models. Makes large history libraries browsable without manual curation. Builds on existing
Daily / weekly writing digest Generate a private summary of what the user dictated, key decisions, action items, and time saved. Turns the Stats tab from a dashboard into an actionable reflection tool. Builds on existing
Deck "Send to" destinations Send selected items to Obsidian, Notion, Todoist, a new email, a calendar event, or a file. The meeting exporter already supports multiple formats; extending this to the Deck makes it a dispatch hub. High impact Builds on existing
Folders / collections Let users organise Deck items into named collections, not just favourites. Easier to manage long history; can reuse Reader collections logic. Quick win
Duplicate detection & merging Detect near-duplicate clipboard or transcript items and offer to merge them. Keeps the Deck clean as clipboard capture runs continuously. Quick win
Transcript versioning / diff Keep versions of a Prompt-mode rewrite or a Deck job so users can compare iterations. Important for AI-shaped writing where users want to see what changed. Builds on existing
AI-suggested presets Suggest a Deck preset based on the content of selected items (e.g. "Summarise" for a long article). Lowers the cognitive load of choosing among 25 presets. Builds on existing

5Meeting intelligence

Mumble already has a Meetings tab with diarisation, summaries, and exports. These ideas make it a complete meeting tool.

FeatureWhat it would doWhy it mattersStatus
System audio + microphone mix Capture both sides of a video call via WASAPI / CoreAudio / PulseAudio loopback, mixed with the mic. The biggest blocker for the Meetings feature; already planned in the roadmap but worth restating. High impact Heavy / owner call
Click-to-play audio synced to transcript Click any transcript segment to play the meeting audio from that timestamp. meeting_store.py already saves start_sec/end_sec and audio_path; mostly a UI addition. Quick win Builds on existing
Speaker voice enrolment Let users tag a few seconds of each speaker's voice and store a local embedding for persistent names. Turns "Speaker 1/2/3" into "Alice / Bob / Carol" across meetings; can use pyannote.audio embeddings locally. High impact Builds on existing
Live meeting transcription Show a continuously updating transcript with diarisation during the call, not just after. Turns Mumble into a real-time captioning tool for the user's own meetings. Heavy / owner call
Action item tracking Track extracted action items with status, owner, and due date across meetings. Moves from "extract once" to a lightweight meeting task manager. Builds on existing
Calendar integration & auto-titling Read the user's calendar to auto-title meetings and tag participants. Saves manual naming; requires local calendar access, no cloud needed. Quick win
Meeting bookmarks Press a hotkey during recording to mark a moment (e.g. "important decision") for later review. Simple and high-value for long meetings. Quick win

6Reader & text-to-speech

The Reader parses many document formats and reads them aloud. These ideas extend it in both directions.

FeatureWhat it would doWhy it mattersStatus
Global "read aloud" hotkey for selected text Highlight text in any app, press a hotkey, and Mumble reads it via the existing TTS pipeline. The inverse of dictation; makes Mumble an accessibility layer for the whole OS. High impact Builds on existing
Reader import from URL Paste a URL and Mumble fetches the article, extracts readable content, and adds it to the library. reader_parser.py already parses HTML; only a fetch step is missing. Quick win Builds on existing
Article readability extraction Strip navigation, ads, and comments from web pages before reading, similar to browser Reader Mode. Improves the URL-import experience; can reuse BeautifulSoup logic. Quick win
Dictated annotations while reading While a document is playing, dictate a note that is attached to the current word/position. Combines Mumble's two strengths: reading and dictation. Builds on existing
Local TTS voices Support local voices such as Piper or Coqui for users who do not want cloud TTS. Keeps Reader fully offline; aligns with local-first posture. Builds on existing
Audiobook export Export a Reader document as a single MP3/M4B file with chapters derived from headings. Lets users consume long documents offline on other devices. Heavy / owner call

7Integrations & workflows

Ideas that connect Mumble to the rest of the user's tools without compromising the local-first core.

FeatureWhat it would doWhy it mattersStatus
Obsidian / Notion / Roam plugins Send a transcript or meeting summary directly to a note-taking app. Knowledge workers already live in these apps; this closes the loop. Builds on existing
Task manager integrations Send action items to Todoist, Things, Microsoft To Do, etc. Turns meeting action extraction into real task creation. Builds on existing
Email client integration Detect an open compose window and auto-format dictated text as an email body. Reduces mode switches for email-heavy users. Builds on existing
Local API / webhook Expose a small authenticated local HTTP API so tools like n8n, Zapier (local), or AutoHotkey can trigger Mumble. Power-user automation without adding cloud dependencies. Builds on existing
CLI mode Run Mumble from the terminal: mumble --record, mumble --paste-last, mumble --process-meeting file.wav. Useful for scripting, CI, and power users. Quick win
Watch folder for batch import Drop WAV/MP3/M4A files into a folder and Mumble transcribes and diarises them automatically. Batch processing for podcasts, interview recordings, or old meeting files. Quick win

8Privacy, sync & data ownership

Features that strengthen Mumble's privacy promise and give users more control over their data.

FeatureWhat it would doWhy it mattersStatus
User-owned sync backends Support WebDAV, S3-compatible storage, Google Drive, Dropbox, or a "sync folder" instead of only Supabase. Aligns better with local-first than a single third-party backend; currently cloud sync is Supabase-only. High impact Heavy / owner call
End-to-end encrypted cloud sync Encrypt data on the client before sending it to any sync backend. Allows cloud convenience without trusting the server. Heavy / owner call
Full data export / import archive One-click export of history, meetings, reader library, settings, and favourites to a documented zip archive. Makes Mumble feel like a tool users truly own and can migrate. Quick win
Local data encryption at rest Optionally encrypt the Mumble data directory with a user password. Important for shared machines or sensitive work. Heavy / owner call
Automatic snapshots Keep periodic snapshots of history and settings so a bad sync or crash is recoverable. Complements the atomic-write design with versioned recovery. Quick win
Portable mode Run Mumble from a USB drive or a chosen folder with all data stored alongside the app. Useful for users who move between machines or do not want data in AppData. Builds on existing

9Performance & platform

Platform-specific acceleration and performance tooling.

FeatureWhat it would doWhy it mattersStatus
DirectML / ONNX STT backend Use sherpa-onnx with DirectML so AMD, Intel, and NPU users get GPU acceleration, not just NVIDIA CUDA. Architecture review flagged this as high-impact for ~40% of Windows users. High impact Heavy / owner call
macOS Neural Engine / FluidAudio Use Apple Neural Engine for STT on Apple Silicon, with faster-whisper as fallback for unsupported languages. Could be 5–10× faster with far less RAM and battery; already planned. High impact Heavy / owner call
Linux ARM / whisper.cpp fallback Add an optimised ARM path for Linux devices such as Raspberry Pi and ARM laptops. Broadens the Linux port to low-power devices. Builds on existing
GPU selection UI Let users choose which GPU or NPU Mumble uses for STT / local LLM. Laptops with dGPUs and hybrid graphics need explicit control. Quick win
Model download manager Show progress, estimated disk space, and RAM for each downloadable model. Makes onboarding less opaque when models are large. Quick win
Resource saver auto-trigger Automatically enable Resource Saver when on battery or when CPU usage is high. Improves laptop battery life without requiring the user to remember the toggle. Quick win

10Accessibility & usability

Small but important improvements that make Mumble easier for more people.

FeatureWhat it would doWhy it mattersStatus
Command palette Ctrl+Shift+P (or a voice trigger) opens a searchable palette of every Mumble action. Makes the app truly keyboard-first and discoverable. High impact Quick win
Onboarding voice tour A short interactive tour where the user actually dictates sample sentences and sees the results. Onboarding is voice-first, so the tutorial should be too. Quick win
Screen reader labels & focus Full ARIA labels, focus management, and screen-reader announcements for the web UI. Required for users who rely on assistive technology. Quick win
High contrast & large text modes Systematic high-contrast theme and global font scaling beyond the existing responsive scaling. Broadens accessibility without changing the default premium look. Builds on existing
Sticky keys / alternate activation Support one-handed activation methods: sticky hotkeys, mouse-button dictation, or tap sequences. Important for users with motor disabilities. Quick win
Voice control of the Mumble UI Commands like "open history", "show stats", or "switch to settings" control the app itself. Brings the voice-first philosophy to the main window as well as dictation. Builds on existing

11Ecosystem & extensibility

Ideas that let Mumble grow without the core team building every integration.

FeatureWhat it would doWhy it mattersStatus
Plugin / extension registry Allow users to add custom reader parsers, STT/LLM/TTS providers, and Deck presets via a documented API. reader_parser.py already has a clean registry pattern; expand it across the app. High impact Builds on existing
Custom provider system Let users add arbitrary OpenAI-compatible endpoints for STT, LLM, and TTS without code changes. Keeps Mumble provider-agnostic and future-proof. Builds on existing
Community preset gallery A curated list of user-contributed Deck presets with one-click import. Helps users discover powerful workflows without writing prompts. Quick win
Self-hosted update server Support a custom manifest URL and signing key for enterprise or personal update feeds. Lets organisations control their own update channel; fits the existing update.py architecture. Builds on existing

Summary — highest-impact picks

These are the ideas that would deliver the most user value relative to the work already present in the codebase:

  1. Pre-paste preview bubble — directly reduces the biggest user fear (wrong text landing somewhere).
  2. Semantic search across the Deck — turns accumulated transcripts into a real knowledge base.
  3. System-audio mix for Meetings — unlocks the Meetings feature for its intended use case.
  4. Adaptive vocabulary & correction learning — creates a compounding accuracy improvement for every user.
  5. User-owned sync backends — better fits the privacy promise than a single cloud backend.
  6. Global read-aloud hotkey — the natural inverse of dictation and a strong accessibility feature.
  7. Plugin / extension registry — lets Mumble grow beyond what the core team can build.
Honesty guardrail. This catalogue is a garden of possibilities, not a commitment. Any feature that implies a capability Mumble does not yet have must not be shown in the app UI until it is genuinely wired to real data. See STATUS.html §7 for the "depicted-but-not-real" rule.
