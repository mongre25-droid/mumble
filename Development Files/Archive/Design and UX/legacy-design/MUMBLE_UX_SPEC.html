Screen-by-Screen Contract

Mumble UX Spec

◆Version: 3.1.0 (current with the app, 2026-06-12)
◆Audience: UX Pilot — and any designer/developer producing Mumble screens
◆Status: the single source of truth — element behaviour is contractual, not aspirational
In plain terms

Mumble lets you talk to your computer and have your words appear as typed text — anywhere, in any app. You hit a hotkey, speak, hit it again, and a second later polished text lands wherever your cursor was.

This document is the rulebook for how every part of that experience looks and behaves. It describes each screen, every button and dot on it, and exactly what happens when you use it. The important promise: the designs drawn from this document get wired straight to the real software behind Mumble. So if a control isn't written down here, the software can't do it — and a designer should flag it rather than invent it.

1What Mumble Is

Mumble is a private, on-device voice-to-text desktop app for Windows (with a macOS port). The core loop:

1
PRESS & SPEAK

The user presses Ctrl+Win anywhere, in any app. A small floating "island" appears and Mumble records the microphone.

2
PRESS AGAIN

The user speaks, then presses Ctrl+Win again.

3
TRANSCRIBE & PASTE

Mumble transcribes the audio locally (faster-whisper — audio never leaves the device), optionally shapes the text with a cloud AI (the user's own API key), and pastes the result at the cursor in whatever app they were using.

Everything else in the product supports that loop: smart modes that shape the output (email, list, prompt…), the Deck (Ctrl+Alt+V — a mini dashboard where previously captured material is pasted, favourited, or run through AI presets), a history of everything transcribed/copied, statistics, and settings.

The whole experience takes about one second for plain dictation. Latency is a core product value; nothing in the UI may block the dictation loop. The one deliberate exception is the Deck's AI-job lane, which is allowed to think for several seconds because it does heavier work.

1.2 Design language — "Golden Black"

In plain terms

Mumble looks like one thing: black and gold. Near-black surfaces, gold accents, soft rounded shapes with a subtle glassy depth. The only other colours allowed are a small fixed set of "mode" colours (each smart mode has its own hue) plus red/amber/green for status. Anything that isn't black-family, gold-family, a mode accent, or a status colour simply shouldn't appear.

The colourway is BLACK & GOLD — nothing else is a brand colour. Use shade variations of both freely (near-blacks for surfaces/elevation, gold tints from dim to bright for accents, highlights, and 3D/liquid-glass depth). Other colours exist ONLY as functional highlights with a job to do: the per-mode accents (table below, contractual), status red/amber/green, and nothing more. No burgundy, no cherry-as-brand, no stray greens/oranges on utility icons — if a colour isn't black-family, gold-family, a mode accent, or a status colour, it shouldn't exist.

  • Backgrounds: near-black #0A0A0B (app), #121110 (cards/surfaces), #1A1916 (elevated/hover), borders #2A2820.
  • Text: warm white #F3EEE1 (primary), #B6AE99 (dim), #7C745F (muted).
  • Primary accent: gold #D4AF37, hover/bright #EBCB65.
  • Status: red #D9544D, amber #E0A92E, success green #3A8A3A/#5AB85A.
  • Shape: generously rounded (cards 18–24px radius, pills fully rounded), soft 1px warm borders, subtle radial-gold glows on hero/feature cards.
  • Type: Inter / Segoe UI. Small and information-dense; body copy mostly 11–13px.
  • Tone of copy: short, confident, benefit-first. British English.

Liquid-glass ("raised 3D") — approved direction, with performance rules

In plain terms

The fancy "glass" look — surfaces that seem to have depth, light catching the top edge, soft shadows, a gentle spring on hover — is approved. But one ingredient (the live blur that re-samples whatever sits behind an element) is expensive for the graphics chip every time the screen moves. The rule of thumb: use the real blur only on a few small floating bits, fake it on the big cards (which are nearly opaque anyway, so nobody can see the blur), and never animate it.

The raised liquid-glass look (gradient surfaces, inset top highlights, soft drop shadows, springy hover lifts) is approved. The ONE expensive ingredient is backdrop-filter: blur() — every blurred element re-samples the pixels behind it on the GPU whenever anything moves (scroll, animation). Rules:

  1. Real backdrop-filter only where it's visible: small chrome that sits over CONTENT — the nav pill, status chip, the hero waveform container. Budget: ≤ 6–8 blurred elements per screen (the current draft has 26).
  2. Cards use FAKE glass. The draft's card surfaces are 85–98% opaque (rgba(…, 0.85–0.98)), so the blur behind them is invisible anyway — keep the exact gradient/inset-highlight/shadow recipe and simply drop backdrop-filter from .liquid-glass-card / .hero-card-glass. Identical look, ~80% of the GPU cost gone.
  3. Transform/opacity-only animation (the draft already does this — hover translateY/scale). Never animate filter/backdrop-filter.
  4. Idle animation is minimal (Standard tier): the island's gentle pulse plus the hero waveform's live wave (20 bars × five keyframe personalities; idle runs at ~2.6× slower tempo — deliberate, never frantic (owner 2026-06-12); recording restores the full tempo; off in Lite / reduced-motion / hidden). Nothing else moves at idle. Enhanced is a SHIPPED third tier (owner approved 2026-06-12): real glass everywhere, ambient aurora + gold dust, view transitions, hero light sweep, richer micro-interactions — selectable in onboarding + Settings → System; ?enhanced + Preview Enhanced Mode.bat remain as the demo path.
  5. Vendor Tailwind/FontAwesome/fonts locally before shipping — no CDNs at runtime (offline app, privacy posture; the CDN Tailwind build is dev-only). (Done: the shipped UI is hand-written CSS + inline SVG + system fonts — zero runtime network.)
  6. Lite mode (v3.0.0): the ui_effects setting (standard | lite) renders the SAME layout with every GPU-expensive ingredient disabled (body.lite: no backdrop-filter, light shadows, no ambient animation, no hover lift). Offered in onboarding step 5, changeable in Settings → System. prefers-reduced-motion is honoured independently, and ambient animation pauses whenever the window is hidden.

2.2 The mode key — the single most important interaction rule

In plain terms

Modes only switch on while you physically hold the mode key (Right Shift). Hold it and say "email" and Mumble formats an email; let go and "email" is just the word "email". Because holding the key proves you meant it, Mumble can match the keyword very loosely — even a mishearing or a single clipped letter counts. A white ring on the island confirms the key is down.

Mode detection happens only while the mode key is physically held. Without it, every utterance is plain text — saying "email" just types the word "email". While held, the spoken keyword (prompt / email / list / reply / foreign / convert) selects the mode — "context"/"contacts" are NOT keywords (a hard stop-list protects them from convert's loose matching); saying them just types the words (material-as-context lives in the Deck); matching is deliberately aggressive (mishearings like "emal"/"concert", even a clipped single letter) because the held key proves intent. A white armed ring shows on the island while the key is down. If the key was held but no keyword was caught, the AI gives a free second opinion and may suggest a mode via a violet chip (§3).

2.3 Spoken commands — REMOVED (v3.1.0)

Voice-triggered formatting is gone (owner decision: false positives — saying "new line" mid-sentence reformatted text people didn't want reformatted). Saying "new line" / "new paragraph" / "bullet point" now just types those words. Structure — paragraphs, bullets, numbered lists — is the AI polish's job (and List mode for deliberate lists). Don't design any spoken-command UI; the Home card was replaced by an Instant Web Search feature card.

(Engine note: detection still exists behind formatting.format_transcript(commands=True) for back-compat, but the live app passes commands=False.)

2.4 Personal vocabulary (affects transcription quality everywhere)

The user lists their names/brands/jargon once in Settings; Mumble biases the recogniser toward those words and auto-corrects mis-heard variants (phonetic + fuzzy matching), flagging uncertain ones for the AI. Advanced users can add exact wrong = right pairs. No screen other than Settings exposes this, but designers should know transcripts shown in History reflect these corrections.

3The Island Overlay (small pill)

In plain terms

The "island" is a tiny status pill that pops up at the bottom-centre of your screen while you dictate. It has no buttons — you can't click it, the mouse passes right through it. Its only job is to tell you what Mumble is doing right now: listening, transcribing, building, done. It hides when idle and hops to whichever monitor your active window is on.

A compact pill, bottom-centre of the active monitor, always on top, click-through (never intercepts the mouse), hidden when idle. Re-centres onto whichever monitor holds the focused window. It is pure status — no buttons.

Built to the HTML-island reference (v3.0.0): the pill is one content-sized capsule laid out as status dot · live animation · readable state label ("Listening", "Building · Email", "Done"). The re-paste hint and the violet mode-suggestion now render their text inline in the same pill (gold/violet pulse) — the old secondary half-size "mini" pill above it is retired. Deck jobs show the label of the composed modes (e.g. "Building · Context + Email") alongside the dual-colour dots.

4The Deck (Ctrl+Alt+V) — flagship feature

In plain terms

The Deck is a little dashboard you summon with Ctrl+Alt+V. It shows one searchable list of everything you've recently dictated, copied, or had Mumble generate. Two things you can do with it: (1) quick-paste — pick a row, hit Enter, it drops in at your cursor; or (2) run an AI job — tick some items, pick a "preset" (like Summarise or Reply) and/or a mode (like Email), hit Go, and Mumble thinks for a few seconds then pastes the result. It replaced two older features and is the only Mumble overlay you can actually click.

4.1 When it opens

Press Ctrl+Alt+V anywhere (the binding is configurable; mouse buttons work too). The Deck replaced BOTH the old Paste Palette and the voice-triggered Context Island — "context" is not a spoken trigger any more; using your material as context simply lives here.

4.4 What happens on Go (the AI contract)

  • The chosen preset's full instruction becomes the AI's system directive (never pasted). No preset → a default "produce the most useful faithful rendering" job.
  • A chosen mode appends an output-form directive (e.g. Email → "format as a ready-to-send email"), so Preset × Mode compose ("a summarised email").
  • The checked items are sent labelled [TRANSCRIPT — time] / [CLIPBOARD — time] / [PROMPT — time]; the labels are declared metadata, never content.
  • The AI is told explicitly it is being instructed, not transcribing, and runs with a long reasoning budget — this lane is the slow, thoughtful one; building may take several seconds and the island shows the dual-colour building state the whole time. Transient failures retry once.
  • If the AI definitively fails, Mumble never dumps the raw material: it notifies "Deck needs Pro AI" and produces nothing.

5The Main Window — screen by screen

In plain terms

The main window is the full app you open from the tray icon. It's a tall, fairly narrow column with four tabs — Home, History, Stats, Settings — and a first-run wizard the very first time you launch. The whole thing is built in HTML/CSS/JS inside a lightweight desktop shell, so what's drawn here maps directly to the running app.

Canvas / window size (updated 2026-06-12 — the TALL-COLUMN contract): the window opens as a tall, moderately narrow column: 920 wide × (work-area height − 130), clamped 600–1400 — generous vertical workspace, with desktop always visible above and below so it never feels fullscreen and the title bar stays grabbable. The window is freely resizable (minimum 640×480; the content column re-centres and clamps at 1280 on ultrawide); every launch returns to the default, and Settings → System → "Reset window size" snaps back instantly via Api.reset_window_size. Design ONE canvas — the fluid behaviour is the implementation's job, not a design variant. Vertical scrolling within a tab is fine.

Golden Black, centred title bar (logo + "Mumble" + tagline; live status dot top-right showing Ready/Recording/Error), pill-style nav: Home · History · Stats · Settings. Platform-neutral chrome: no macOS traffic-light buttons, no OS-specific window furniture — Mumble ships on Windows (and a macOS port) and must look native to neither.

5.0 First-run onboarding (the very first screen a new user sees)

A centred 6-step wizard — no main nav bar (it's pre-app), a numbered step-progress indicator on top, Back/Next at the bottom, a quiet "Skip for now" on optional steps. Same liquid-glass black & gold; a gold waveform motif on the welcome/finish steps. The through-line is trust + the free key: say "audio never leaves your device" early and again at the key step, and funnel everyone toward Cerebras without hard-blocking (the app works locally without a key — just no AI polish).

hold Right Shift, say "email …" → armed ring → same pipeline → Building/flash in blue → a formatted email is pasted.

3. Deck job flow

Ctrl+Alt+V → the Deck opens → user searches/filters, picks a preset and/or a MODE chip (the hub enters job mode), clicks items to check them as material → Go (or Enter) → hub closes, building shows Deck-teal/mode dual colours (this lane thinks longer — seconds, not instants) → result pasted + recorded; Esc at any point = nothing happens. (Saying "context" by voice does nothing — it's an ordinary word.)

4. Suggestion redo

armed but keyword missed → AI suggests → violet chip → re-press key + say "prompt" → previous transcript re-runs as a prompt.

5. Voice search

Ctrl+Alt+S with selection → browser opens search; without → record, stop, transcript searched.

6. Re-paste

output couldn't land → hint pill → user clicks the target field → Ctrl+Alt+V → the Deck opens with the result as the top row → Enter.
