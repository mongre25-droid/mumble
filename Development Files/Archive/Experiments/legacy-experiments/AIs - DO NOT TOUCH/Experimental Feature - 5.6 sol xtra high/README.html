Operator

A self-contained, hands-free desktop-assistant experiment by 5.6 sol xtra high. It explores how spoken PC automation could feel inside Mumble without joining Mumble’s runtime or normal application flow.

Isolated prototype · Windows-first
In plain terms: open Launch Experiment.bat, press Right Shift, and describe what you want. Operator presents an inspectable action plan before running the narrow set of actions that are genuinely connected. The full interface also opens directly from index.html in preview mode.

Run it

Full local-host experience

  1. Double-click Launch Experiment.bat.
  2. Your default browser opens http://127.0.0.1:8765/.
  3. Press Right Shift or tap the gold microphone orb.
  4. Type the command that the unconnected audio adapter would have transcribed.
  5. Review the plan. Only an entirely executable plan enables Run plan.
  6. Close the terminal or press Ctrl+C to stop the host and its temporary shortcut watcher.

Interface-only preview

Open index.html directly. All screens, planning presentation, the milestone popup and the Archetype flow remain interactive; desktop action buttons stay disabled and say why.

Architecture

01Right Shift / command
02Pure action planner
03Visible review gate
04Allow-listed adapter
  • assistant_core.py is a pure, dependency-free intent-to-plan layer. Its output is serialisable and always rebuilt server-side before execution.
  • desktop_host.py is an optional localhost server and experimental Windows adapter. It binds only to 127.0.0.1, has no persistent service, and exits cleanly.
  • index.html, styles.css and app.js form the zero-CDN Golden Black UI. The interface is responsive, keyboard navigable, reduced-motion aware and pauses animation/polling when unfocused.
  • The milestone and report store only four namespaced preview values in browser local storage. They never read Mumble settings, stats or history.

Safety and honesty

Every planned step carries one of three states: reviewed, confirmation, or blocked. The host refuses partial workflows when any step is unimplemented. Unknown applications are not passed to a shell, URLs are restricted to HTTP(S), paths must exist, and action plans received from the page are discarded and rebuilt from their original command before execution.

The experiment deliberately does not use browser speech recognition because implementations may send audio to a cloud service, conflicting with Mumble’s local-first promise. A production spike should connect Mumble’s existing local transcript output through an authenticated, explicit experiment seam.

Milestone and Archetype flow

The popup is not part of the app boot flow. Press Simulate 20 hours to set the experiment-only hours value to 20.4; the thank-you appears once and records its own seen flag. The X and LinkedIn controls are intentionally placeholders and announce that fact.

The optional report moves through three screens: premium explanation → newsletter consent → sample report. Email syntax and opt-in are validated locally, but the address is never stored or sent. Every screen says that transcript analysis is absent and every report claim is sample copy.

Tests

python -m unittest -v test_assistant_core.py
python -m py_compile assistant_core.py desktop_host.py
python desktop_host.py --no-browser

The planner test suite covers allow-listed apps, unknown-app refusal, folders, window focus, Brave and site-specific search, existing-tab gating, workflow order, file-edit blocking, paste gating, URL normalisation and empty input.

Production integration boundary

No production integration was made. If this concept later proceeds, the recommended seam is a single experiment adapter registered through Mumble’s existing bindings.py funnel, receiving completed local transcripts from the controller and returning explicit action results. Do not copy the experimental Right Shift poller into production.
