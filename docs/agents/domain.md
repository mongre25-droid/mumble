# Domain documentation

Mumble is a single-context project. Before substantive work, read `Development Files/Core/README.html`, then use the relevant authoritative Core record:

- `STATUS.html` for present state, active priorities, known bugs, release gates, and unfinished work.
- `HANDBOOK.html` for current architecture, testing, packaging, porting, and release procedures.
- `LOGS.html` for completed milestones.
- `README.html` for the stable product contract, repository layout, and working agreement.

Do not create duplicate `CONTEXT.md`, `CONTEXT-MAP.md`, ADR, status, audit, bug, or handoff records when the information belongs in an established Core record or GitHub issue. Use the terminology in the current Core records in issues, specifications, tests, and implementation notes.

If a proposed change contradicts the current product contract or a recorded decision, state the conflict explicitly and resolve it through the Wayfinder map before implementation.
